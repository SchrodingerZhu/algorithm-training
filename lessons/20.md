# 20 · ETT 的第一种扩展：连通分量点权和

已经能连边、断边并判断连通性后，只增加一个新要求：每个节点有一个整数权值，查询它所在整棵树的点权和。

这一步沿用第 19 题的全部游走表示与连断边操作，只学习怎样增加聚合信息。权值就是整数，允许正数、零和负数。

## 题目与接口

初始有 n 个孤立节点，节点 u 的权值为 values[u]。

```cpp
std::vector<long long> componentSum(
    const std::vector<long long>& values,
    const std::vector<std::array<long long, 3>>& operations);
```

| 操作 | 含义 |
|---|---|
| `{0,u,v}` | 添加无向边 u—v；自环或已经连通则忽略 |
| `{1,u,v}` | 删除直接边 u—v；不存在则忽略，参数顺序无关 |
| `{2,u,w}` | 将 u 的点权赋为 w |
| `{3,u,0}` | 查询 u 所在连通分量内所有节点的点权和 |

只返回类型 3 的答案。类型 2 的第三项是权值，其他有效参数是节点编号；类型 3 的第三项固定为 0。查询孤立点就返回它自己的当前点权。

`1 ≤ n = values.size() ≤ 100000`，操作数不超过 200000。初始权值和赋值在 `[-10⁹,10⁹]`，节点编号和操作类型合法。没有查询返回空数组，同一 Solution 对象的多次调用独立。目标为每次期望 `O(log n)`，辅助空间 `O(n)`，另计返回数组。不需要 main 或输入输出。

```text
values = [2,-1,4,100]
operations = [[0,0,1], [0,1,2], [0,1,3], [3,0,0],
              [2,1,5], [3,2,0], [1,1,3], [3,0,0], [3,3,0]]
answer = [105,111,11,100]
```

最初四点相连，和为 `2-1+4+100=105`。修改节点 1 后总和为 111。删除 1—3 后，两个分量的和分别为 11 和 100。这里查询的是整个分量，旁支也计入。

## 第一步：权值应该放在哪条记录上？

回顾第 19 题：每个节点有唯一的 V(u)，每条边有 E(u,v)、E(v,u) 两条记录。沿树行走可能多次经过 u，但 V(u) 只出现一次。

因此只给 V(u) 赋点权，所有 E 记录的值设为 0。例如：

```text
边：0—1，0—2；点权：[2,-1,4]
记录：V(0), E(0,1), V(1), E(1,0), E(0,2), V(2), E(2,0)
权值：  2      0      -1      0        0       4       0
```

整条记录序列的和恰好是 `2-1+4=5`。不要在每次经过某个节点时都加它的权值，否则连接多条边的节点会重复计数。

## 第二步：在辅助二叉树中维护 sum

在第 19 题的 Treap 节点中增加 `value` 和 `sum`，两者都用 long long。空节点的 sum 为 0。重新聚合时：

```text
pull(x):
    size[x] = size[left[x]] + 1 + size[right[x]]
    sum[x] = sum[left[x]] + value[x] + sum[right[x]]
```

size 仍统计全部记录，用于 split 与 rank；sum 统计记录权值。不能因为边记录权值为零就不计入 size。

split/merge 中原本需要 pull 的地方，现在同时更新 size 和 sum。初始化 V 卡时 sum=value；新建或重用 E 卡时 value=sum=0。

## 第三步：查询整棵辅助树的和

```text
componentSum(u):
    t = root(vertex[u])
    return sum[t]
```

t 的辅助子树就是整条游走，恰好含该分量的全部 V 记录各一次。无论现在从哪个节点开始游走，或者 Treap 的根是哪张记录，sum[t] 都是相同的分量和。

`reroot` 只是把 `A+B` 变成 `B+A`，不会改变总和；link 把两个分量的记录和两张零权边记录拼在一起；cut 将记录分成两侧。只要切拼时维护 pull，无需额外遍历实际树来修复总和。

## 第四步：点赋值后修复辅助祖先

```text
setValue(u,w):
    x = vertex[u]
    value[x] = w
    while x 非空：
        pull(x)
        x = parent[x]
```

这里 parent 是普通 Treap 父指针。x 的辅助祖先统计包含旧值，所以从下向上重算；它们与实际森林中 u 的祖先没有关系。没有懒标记时，这一条父链就足够了。

赋值覆盖旧值，不是增加差值。断边不重置任何 V 记录；断开的节点修改后再连回，应保留新值。

## 第五步：用小例子检查聚合范围

先只做单点赋值与查询，再连成三节点链，最后加一个大权值旁支。分量查询必须包含旁支；这与第 18 题的路径查询不同。

<details><summary>为什么每一步仍是对数复杂度？</summary>

pull 多做常数次加法，不改变 split/merge 的复杂度。查询沿一条辅助父链找根，赋值沿一条辅助父链向上修复，期望长度都是 `O(log n)`。记录数与回收规则沿用第 19 题，空间仍是 `O(n)`。

</details>

最多 100000 个绝对值不超过 10⁹ 的点权，和的绝对值不超过 10¹⁴，所以返回值也用 long long。0、-1 都是正常答案，这里无需 optional，因为每个节点总属于一个分量。
