# 07 · 倍增祖先表：第 k 个祖先

## 题目

给定一棵包含 `n` 个节点的有根树，节点编号为 `0` 到 `n - 1`，根节点固定为 `0`。树的结构通过数组 `parent` 给出：

- `parent[v] = u` 表示节点 `v` 的直接父节点是 `u`，即从 `v` 向根走一步会到达 `u`。
- 根节点没有父节点，所以 `parent[0] = -1`。
- `-1` 表示“节点不存在”，不是一个可以访问的节点编号。
- 输入保证是一棵合法的树：从任何节点不断走向父节点，最终都会到达根 `0`，不会出现环。

现在给出 `q` 个查询。每个查询 `queries[i] = {v, k}` 要求你返回：**从节点 `v` 开始，沿父节点方向恰好走 `k` 步后到达的节点编号**。这个节点称为 `v` 的第 `k` 个祖先。

- `k = 0`：不移动，返回 `v` 自己。
- `k = 1`：返回直接父节点。
- `k = 2`：返回父节点的父节点。
- 如果恰好走到根，返回 `0`；如果所需步数超过了到根的距离，返回 `-1`。

返回一个长度为 `q` 的数组 `answer`，其中 `answer[i]` 对应第 `i` 个输入查询。树的结构始终不变，每个查询都从它自己的 `v` 开始，查询之间不会改变彼此的起点。

## 怎样理解父节点数组

例如：

```text
节点编号：  0  1  2  3
parent：  -1  0  0  1
```

这表示 `1` 和 `2` 的父节点都是 `0`，`3` 的父节点是 `1`。树的形状是：

```text
0
├── 1
│   └── 3
└── 2
```

从 `3` 向上走的过程为 `3 → 1 → 0`。走 `0`、`1`、`2` 步，分别到达 `3`、`1`、`0`；要求走 `3` 步时，祖先不存在，返回 `-1`。

节点编号只是标识，**父节点编号不保证小于子节点编号**。例如 `parent[1] = 3` 完全合法，不能根据编号大小判断谁更靠近根。

## 函数接口

在 `Solution` 类中实现：

```cpp
std::vector<int>
kthAncestors(const std::vector<int> &parent,
             const std::vector<std::array<long long, 2>> &queries);
```

| 参数或返回值 | 含义 |
|---|---|
| `parent` | 长度为 `n` 的父节点数组，`parent[0] = -1` |
| `queries[i][0]` | 查询的起点 `v` |
| `queries[i][1]` | 向上走的步数 `k`，可能很大，因此使用 `long long` |
| 返回值 `answer[i]` | 到达的节点编号；祖先不存在时为 `-1` |

只需要完成这个成员函数及其辅助代码，不需要编写 `main`、读取标准输入或打印答案。评测程序会直接调用函数。

## 数据范围与约定

- `1 ≤ n = parent.size() ≤ 200000`。
- `0 ≤ q = queries.size() ≤ 200000`。
- `parent[0] = -1`；对于 `v > 0`，有 `0 ≤ parent[v] < n`。整个数组保证描述一棵以 `0` 为根的合法树，无须检查输入是否合法。
- 每个查询满足 `0 ≤ v < n`、`0 ≤ k ≤ 10^18`。
- 查询顺序任意，可以出现重复查询，返回结果必须保持输入顺序。
- 查询列表可以为空，此时返回空数组。
- 树可以只有根节点，也可以是一条包含全部 `n` 个节点的长链。
- 同一个 `Solution` 对象可能被多次调用，每次传入不同的树；各次调用应独立计算。

## 示例

### 示例 1：从自己走到根，再越过根

```text
parent  = [-1, 0, 0, 1]
queries = [[3, 0], [3, 1], [3, 2], [3, 3]]
answer  = [3, 1, 0, -1]
```

| 查询 | 向上走的过程 | 答案 |
|---|---|---|
| `{3, 0}` | 留在节点 `3` | `3` |
| `{3, 1}` | `3 → 1` | `1` |
| `{3, 2}` | `3 → 1 → 0` | `0` |
| `{3, 3}` | 到达 `0` 后还需要走一步，但根没有父节点 | `-1` |

### 示例 2：父节点编号可以更大

```text
parent  = [-1, 3, 0, 2]
queries = [[1, 1], [1, 2], [1, 3], [1, 4], [3, 2]]
answer  = [3, 2, 0, -1, 0]
```

这棵树从节点 `1` 向上走的路径是 `1 → 3 → 2 → 0`。因此节点 `1` 的第 `3` 个祖先是 `0`，第 `4` 个祖先不存在。最后一个查询从 `3` 重新出发，走两步到达 `0`。

### 示例 3：单节点树与很大的步数

```text
parent  = [-1]
queries = [[0, 0], [0, 1], [0, 1000000000000000000]]
answer  = [0, -1, -1]
```

根节点的第 `0` 个祖先是自己，其余正数步数对应的祖先都不存在。

空查询列表的情况：

```text
parent  = [-1]
queries = []
answer  = []
```

## 算法要求与复杂度

本题要求使用**倍增祖先表**：为固定的树预先保存一些向上跳跃的结果，让全部查询共享这份预处理数据。具体维护什么、如何组合跳跃，可以按需查看下面的提示。

- 预处理时间：`O(n log n)`。
- 每次查询时间：`O(log n)`。
- 总时间：`O((n + q) log n)`。
- 辅助空间：`O(n log n)`；加上返回数组，总空间为 `O(n log n + q)`。

直接逐次访问父节点可以帮助你手算答案，但长链上的一次查询可能需要走 `n - 1` 步，大量查询时不能满足时间目标。

## 分步提示

题目规则到这里已经完整。下面是可选的算法提示，可以先独立思考再逐个展开。

<details>
<summary>提示 1：祖先表中的一项到底保存什么？</summary>

设 `up[j][v]` 表示：从节点 `v` 向上走恰好 `2^j` 步后到达的节点编号；如果不存在，则保存 `-1`。

因此 `up[0][v]` 保存走 `1` 步的结果，`up[1][v]` 保存走 `2` 步的结果，`up[2][v]` 保存走 `4` 步的结果，以此类推。每一项只保存一个节点编号或 `-1`。

注意 `j` 表示跳跃步数的指数，不是节点深度，也不是“第 `j` 个祖先”。节点深度指它到根需要走的步数，根的深度为 `0`。

</details>

<details>
<summary>提示 2：怎样从短跳跃构造长跳跃？</summary>

走 `2^j` 步，可以分成连续两次各走 `2^(j - 1)` 步。第二次跳跃要从第一次到达的节点继续出发。

初始层满足 `up[0][v] = parent[v]`。对于更高层，先取得中间节点 `u = up[j - 1][v]`：如果 `u == -1`，结果仍为 `-1`；否则结果为 `up[j - 1][u]`。不能用 `-1` 访问数组。

按层从小到大构造：先完成所有节点的第 `j - 1` 层，再计算第 `j` 层。这样父节点的编号无论大小，都不会影响依赖关系。

</details>

<details>
<summary>提示 3：怎样回答查询，以及处理很大的 k？</summary>

把步数拆成若干个 `2` 的幂。例如 `13 = 8 + 4 + 1`，可以从起点先跳 `8` 步，再从新的位置跳 `4` 步，最后跳 `1` 步。每次都更新当前位置，遇到 `-1` 就可以结束。

虽然 `k` 最大为 `10^18`，但树里只有 `n` 个节点，任何节点到根最多走 `n - 1` 步。因此 `k >= n` 时可以直接回答 `-1`，剩余查询只需处理 `k < n` 的情况。先检查这个条件，再考虑把 `k` 转为较窄的整数类型。

这样只需要保存覆盖 `n - 1` 步所需的二进制位，共 `O(log n)` 层；`n = 1` 时也要妥善处理表的大小和 `k = 0` 的查询。

从起点组合这些跳跃时，可以思考一个不变量：已经跳过的总步数，加上尚未处理的步数，始终等于原查询的 `k`。

</details>
