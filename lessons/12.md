# 12 · 换根 LCA：同一棵树，不同的祖先关系

给定一棵树，反复回答“如果把某个节点当作根，另外两个节点的最近公共祖先是谁？”每次查询都可以指定不同的根。

换根不会增加或删除边，也不会改变两个节点之间的路径；它改变的是哪一侧朝向根，从而改变父子关系与祖先关系。本题要在一次预处理之后回答所有查询，不能每次换根都重新遍历整棵树、重建祖先表。

## 题目与函数接口

给定数组 `parent`，描述一棵有 `n` 个节点的树。节点编号为 `0, 1, ..., n-1`，输入以节点 `0` 为根：

- `parent[0] = -1`，表示节点 `0` 没有父节点。
- 对每个 `v != 0`，树中有一条连接 `parent[v]` 和 `v` 的无向边。
- `parent` 只是描述这棵树的一种方式。查询指定其他根时，仍使用同一组无向边。

另给定查询数组 `queries`，每个查询严格按 **`{r, u, v}`** 排列：

1. 仅在这次查询中，把节点 `r` 当作树根。
2. 在这个根定义的祖先关系下，求节点 `u` 和 `v` 的最近公共祖先。
3. 返回答案的节点编号。

各查询独立；一次查询指定的根不会延续到下一次查询。下一次使用它自己的 `r`，不需要真的修改输入数组 `parent`。

在 `Solution` 类中实现：

```cpp
std::vector<int>
rerootedLca(const std::vector<int> &parent,
            const std::vector<std::array<int, 3>> &queries);
```

返回数组按查询的输入顺序保存答案。只需要完成这个函数及其辅助代码，不需要编写 `main` 或处理输入输出。

- `1 ≤ n = parent.size() ≤ 200000`，`0 ≤ queries.size() ≤ 200000`。
- 输入保证是一棵合法的树，父节点编号不保证小于子节点编号。
- 每个查询满足 `0 ≤ r, u, v < n`，允许其中任意节点相同，也允许重复查询。
- 查询列表为空时返回空数组。
- 本题没有点权或边权，也没有增加、删除边的操作。
- 同一个 `Solution` 对象可以被多次调用，每次应独立计算。
- 目标：一次 `O(n log n)` 预处理，每次查询 `O(log n)`，辅助空间 `O(n log n)`；另需保存返回数组。

## 最近公共祖先怎样依赖根？

选定根 `r` 后，节点 `x` 的祖先就是从 `r` 到 `x` 的路径上的所有节点，包含 `r` 和 `x` 自身。节点深度是它到根的边数。

节点 `u` 和 `v` 的最近公共祖先（Lowest Common Ancestor，LCA），是它们共同祖先中深度最大的那个。也可以从路径看：从根分别走向 `u` 和 `v`，两条路径起初重合，最后一个共同经过的节点就是 LCA。

因此：

- `u == v` 时，答案是 `u`。
- `r == u` 时，答案是 `u`；`r == v` 时，答案是 `v`。
- 节点编号的大小不代表深度大小。

## 手算同一棵树的三种根

使用以下输入：

```text
节点编号：  0  1  2  3  4
parent：  -1  0  0  1  1
```

它描述的无向边是 `0—1`、`0—2`、`1—3`、`1—4`。先固定要查询的两个节点为 `u = 2`、`v = 4`，只改变根。

### 查询 `{0, 2, 4}`：以 0 为根

```text
        0
       / \
      1   2
     / \
    3   4
```

- 从根到 `2` 的路径是 `0 → 2`。
- 从根到 `4` 的路径是 `0 → 1 → 4`。
- 最后一个共同节点是 `0`，所以返回 `0`。

### 查询 `{3, 2, 4}`：以 3 为根

同一组边改用节点 `3` 作为根来画：

```text
        3
        |
        1
       / \
      0   4
      |
      2
```

- 从根到 `2` 的路径是 `3 → 1 → 0 → 2`。
- 从根到 `4` 的路径是 `3 → 1 → 4`。
- 两条路径先一起经过 `3, 1`，然后分开，所以返回 `1`。

此时节点 `1` 的父节点变成 `3`，节点 `0` 的父节点变成 `1`。这说明输入的 `parent` 并不是所有查询下都成立的父节点表，但它描述的边始终有效。

### 查询 `{4, 2, 4}`：以 4 为根

```text
        4
        |
        1
       / \
      0   3
      |
      2
```

- 从根到 `2` 的路径是 `4 → 1 → 0 → 2`。
- 从根到 `4` 的路径只有节点 `4` 自身。
- 最近公共祖先是 `4`，所以返回 `4`。

三次查询中的 `u, v` 完全相同，边也完全相同，答案却分别为 `0, 1, 4`。变化来自根所定义的祖先方向。

## 完整输入输出示例

```text
parent  = [-1, 0, 0, 1, 1]
queries = [[0, 2, 4], [3, 2, 4], [4, 2, 4],
           [0, 3, 4], [3, 3, 4], [2, 4, 4]]
answer  = [0, 1, 4, 1, 3, 4]
```

前三项已在上面逐步解释。后三项分别是：

| 查询 `{r, u, v}` | 解释 | 答案 |
|---|---|---|
| `{0, 3, 4}` | 原根下，`3` 和 `4` 的父节点都是 `1` | `1` |
| `{3, 3, 4}` | 查询节点 `u` 就是本次的根 | `3` |
| `{2, 4, 4}` | 两个查询节点相同，节点自身就是其最近公共祖先 | `4` |

注意第四次查询明确指定根为 `0`，不能沿用第三次查询的根 `4`。

## 思考与实现提示

朴素方法是：对每个查询，从 `r` 出发遍历无向树，重新计算父节点与深度，再求 LCA。这样一次查询就要 `O(n)` 时间，所有查询达到 `O(nq)`，不符合目标。

下面的提示解释怎样只对原根 `0` 建立一次查询结构。

<details>
<summary>提示 1：换根之后，什么没有变？</summary>

树上任意两个节点之间都有唯一的简单路径，即不重复经过节点的路径。换根不会改变这条路径。

考虑 `r` 到 `u`、`r` 到 `v`、`u` 到 `v` 这三条路径。它们共同包含的唯一节点，就是以 `r` 为根时的 `LCA(u, v)`：从 `r` 出发到这里之后，通向 `u` 和 `v` 的路径分开；若某个端点就是答案，则对应的一段路径长度为零。

可以先在上面的三个图中找到这个节点，再思考如何使用原根下的 LCA 定位它。

</details>

<details>
<summary>提示 2：一次查询只需三个原根下的 LCA</summary>

始终以原根 `0` 预处理祖先表和深度数组。用 `LCA₀` 表示这个固定根下的 LCA。对于查询 `{r, u, v}`，计算：

```text
a = LCA₀(u, v)
b = LCA₀(u, r)
c = LCA₀(v, r)
```

答案是 `a, b, c` 中在**原根 0 下深度最大**的节点。这里始终比较原来的 `depth`，不需要计算换根后的深度。

例如查询 `{3, 2, 4}`：

```text
a = LCA₀(2, 4) = 0，depth[0] = 0
b = LCA₀(2, 3) = 0，depth[0] = 0
c = LCA₀(4, 3) = 1，depth[1] = 1
```

因此答案是节点 `1`。每次只做三次 LCA 查询和常数次比较，总查询时间仍为 `O(log n)`。

</details>

<details>
<summary>提示 3：为什么是这三个节点中最深的那个？</summary>

在原根下，令 `t` 为 `u, v, r` 三个节点共同的最近祖先。考察它们落在 `t` 的哪些孩子子树中。

如果其中两个节点落在同一棵孩子子树里，而第三个在别处或就是 `t`，那么前两个节点的 LCA 在 `t` 下方，另外两对的 LCA 都是 `t`。那个更深的节点，正是连接三点的三条路径共同经过的节点。

如果没有这样的两个节点，则三个两两 LCA 都等于 `t`，路径的共同节点也是 `t`。端点重合时结论仍成立：例如 `u == v`，三条路径的共同节点就是 `u`。

所以 `a, b, c` 要么全部相同，要么其中两个相同、第三个更深。选择原根下最深的节点，就得到三条路径的共同节点，也就是本次换根后的答案。

</details>

## 检查与运行

实现时可复用已有的普通 LCA 查询结构。保持其根、祖先表和深度数组不变，在每个查询外面增加对新根的处理即可。本题返回的是节点编号，不是深度，也不是边权最小值。

重点检查：

1. 单节点树：查询 `{0, 0, 0}` 返回 `0`。
2. `r == 0`：结果应与原根下的普通 LCA 相同。
3. `u == v`、`r == u` 或 `r == v`。
4. 相同的 `u, v` 配上不同的 `r`，以及查询之间切回之前使用过的根。
5. 一条链 `0—1—...—(n-1)`：查询 `{r, 0, n-1}` 应返回 `r`。
6. 父编号大于子编号的输入、空查询列表，以及同一个对象的多次调用。

长链可能达到 200000 个节点；若预处理需要遍历，应使用显式栈、队列或已有的安全方法，避免依赖同样深度的函数递归。
