# 15 · 树链剖分：路径加与路径和

第 14 题已经能把树上路径拆成少量数组区间。这一题保留同样的拆分方法，但修改和查询都作用于整条路径：给路径上的每个节点增加一个数，再查询路径上的点权总和。

新的重点在线段树内部。整段加法需要懒标记，而维护区间和时，必须考虑区间中有多少个节点。

## 题目与函数接口

`parent` 描述一棵根为 `0` 的非空树，`parent[0] = -1`。`values[v]` 是节点 `v` 的初始点权。树的边和根在所有操作期间保持不变。

按输入顺序执行：

| 操作 | 含义 | 是否产生答案 |
|---|---|---|
| `{0, u, v, delta}` | 给 `u` 到 `v` 路径上的每个节点加上 `delta` | 否 |
| `{1, u, v, 0}` | 查询 `u` 到 `v` 路径上的点权总和 | 是 |

两种操作都包含路径的两个端点。修改是**在当前点权上增加** `delta`，不是把点权赋为 `delta`。查询的第四项是占位。

在 `Solution` 类中实现：

```cpp
std::vector<long long>
pathAddSum(const std::vector<int> &parent,
           const std::vector<long long> &values,
           const std::vector<std::array<long long, 4>> &operations);
```

返回数组只保存查询操作的结果，顺序与查询出现的顺序一致。不需要编写 `main` 或处理输入输出。

- `1 ≤ n = parent.size() = values.size() ≤ 200000`。
- `0 ≤ operations.size() ≤ 200000`，所有节点编号从 `0` 开始且合法。
- `|values[v]| ≤ 10⁶`，每次修改满足 `|delta| ≤ 10⁶`；修改后的点权可以超过这个范围。
- 输入树合法，父编号不保证小于子编号。允许 `u == v`、负增量和零增量。
- 没有查询时返回空数组；同一个 `Solution` 对象的多次调用应独立计算。
- 目标：预处理 `O(n)`，每次操作 `O(log² n)`，辅助空间 `O(n)`；另需保存答案。

## 手算：路径加一次，总和增加多少？

```text
parent = [-1, 0, 0]
values = [ 1, 2, 3]

        0:1
       /   \
     1:2   2:3

operations = [[1, 1, 2, 0], [0, 1, 2, 4],
              [1, 1, 2, 0], [1, 0, 0, 0]]
answer     = [6, 18, 5]
```

节点 `1` 到 `2` 的路径是 `1 → 0 → 2`。初始总和为 `2 + 1 + 3 = 6`。

执行 `{0, 1, 2, 4}` 后，路径上的三个节点各加 `4`，按节点编号排列的点权变成 `[5, 6, 7]`。再次查询同一路径，结果为 `6 + 5 + 7 = 18`。最后查询节点 `0` 到自身，结果是 `5`。

总和增加了 `3 × 4 = 12`，而不是只增加 `4`。路径中有多少节点，决定一次加法对总和的影响。

## 第一步：复用第 14 题的路径拆分

仍然计算 `size`、`heavy`、`depth`、`head` 和 `pos`，使同一条重链上的节点在展平数组中连续。初始数组为 `flat[pos[v]] = values[v]`。

对路径 `u` 到 `v`：

1. 两点链头不同时，选择链头更深的一侧，处理从该链头到该端点的整段。
2. 把这个端点移动到其链头的父节点，继续处理剩余路径。
3. 两点链头相同时，处理两点之间的最后一段，然后结束。

这套过程与第 14 题相同。不同之处是“处理一段”的含义：路径加要对该数组区间执行区间加，路径和要查询该区间的和并累加到答案。

所有片段互不重叠，并且合起来恰好覆盖整条路径。这一性质在本题尤其重要：重复取最小值可能掩盖重复计入的问题，但求和或增加点权会直接产生错误。

## 第二步：线段树怎样表示尚未下传的加法？

设某个线段树节点管理半开区间 `[L, R)`，其长度为 `len = R - L`。保存两个量：

| 维护量 | 含义 |
|---|---|
| `sum` | 这个区间中所有点权的当前总和 |
| `lazy` | 已经计入本节点 `sum`、但尚未传给孩子的统一增量 |

如果整个区间都要增加 `d`，直接执行：

```text
sum  += d * len
lazy += d
```

此时本节点的 `sum` 已经正确，不需要立即访问每个叶子。孩子的统计可能还没反映这次修改，所以把需要补做的增量记在 `lazy` 中。

例如一个长度为 `3`、原总和为 `6` 的区间加 `4`，新总和为 `18`，懒标记为 `4`。随后若整段再加 `-1`，新总和为 `15`，累计懒标记为 `3`。加法标记可以直接相加，因为每个点先加 `4` 再加 `-1`，等价于加 `3`。

### 什么时候必须下传？

如果当前操作完全覆盖这个线段树区间，直接修改或读取本节点即可。如果只覆盖其中一部分，就需要访问孩子；在下行之前，先把本节点的 `lazy` 应用到两个孩子：

1. 分别按左右孩子的区间长度更新它们的 `sum`。
2. 把该增量加到两个孩子各自的 `lazy` 上。
3. 将当前节点的 `lazy` 清零。

这叫下传标记，常写成 `push`。区间修改返回时，再令父节点的 `sum` 等于两个孩子的 `sum` 之和，这叫重新聚合，常写成 `pull`。

查询部分区间时也要先下传，否则读到的孩子统计可能还是修改之前的值。查询若完全覆盖当前区间，则可以直接返回其 `sum`，因为整段修改已经计入其中。

## 第三步：公共祖先为什么只处理一次？

每次跨链时，已经处理的片段从链头到当前端点为止。下一端点是链头的父节点，因此这一轮取走的节点不会出现在下一轮中。

两点到达同一条链后，最后一段包含两点之间的所有节点，其中较浅的那个就是原路径的 LCA。只处理这最后一段一次，就会让公共祖先恰好出现一次。

例如主例选择 `1` 为根的重儿子，两条链为 `0 → 1` 和 `2`。路径 `1 → 0 → 2` 被拆成：

```text
第一段：节点 2
最后一段：节点 0、1
```

给两段都加 `4`，根节点 `0` 只增加一次。如果另写成“从 `u` 到 LCA，再从 `v` 到 LCA”，并且两段都包含 LCA，就会把根加两次。

## 数值范围、正确性与复杂度

使用 `long long` 保存点权、区间和、懒标记及长度乘增量。仅把乘法结果存进 `long long` 不一定足够：要保证乘法本身已经在 64 位整数类型中进行，例如让 `delta` 的类型为 `long long`。

最多有 200000 次修改，每次最多增加绝对值 `10⁶`，所以单点绝对值最多约为 `2 × 10¹¹`，整条路径的和最多约为 `4 × 10¹⁶`，在有符号 64 位整数范围内，但远超过 32 位整数。

线段树的标记保证每个数组区间的总和反映所有已执行的修改。树链剖分又把路径分成互不重叠的区间，所以区间修改恰好作用于路径上的所有节点，区间和的总和也恰好等于路径和。

预处理和建线段树需要 `O(n)`。每条路径拆成 `O(log n)` 段，每段的区间加或区间和需要 `O(log n)`，所以每次操作为 `O(log² n)`。剖分数组和线段树共使用 `O(n)` 辅助空间。原树遍历仍应使用显式栈等安全方法，避免长链上的深递归。
