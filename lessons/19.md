# 19 · Euler Tour Tree：从树的游走到动态连通性

维护一片森林，允许连接两棵树、删除一条边，并查询两点是否连通。Euler Tour Tree（ETT）的出发点是：**把树的结构变化转化为一条序列的切分与拼接。**

要理解这个转化，先看树的游走如何包含它的子树。

## 1. 什么是树的 Euler tour？

一般图中的 Euler tour 是经过每条边恰好一次并回到起点的闭合游走。树的一条边删掉后会把树分开；如果沿它走到另一侧，最后还要回来，就必须再次经过这条边。因此在树上，我们把每条无向边看成两个方向：沿一个方向进入，沿相反方向返回。

选一个根，从根出发做 DFS：走到一个孩子，遍历完它的子树，再沿原边返回；所有孩子处理完后结束。这条闭合游走恰好使用每条边的两个方向各一次，称为这里的 Euler tour。

后文始终使用这棵树，先以 0 为根，并先访问孩子 1，再访问孩子 2：

```text
    0
   / \
  1   2
  |
  3
```

从起点开始，每走过一条边就记录到达的节点，包括沿边返回时的到达，得到：

```text
位置：  0  1  2  3  4  5  6
访问：  0  1  3  1  0  2  0
```

这不是「每个节点只记录一次」的 DFS 先序。节点 1 出现两次：第一次从 0 到达，第二次从 3 返回。节点 0 出现三次：出发时，以及分别从两个孩子返回时。

一棵有 k 个节点的树有 k-1 条边，游走经过 `2(k-1)` 次边，所以这种访问序列有 `2k-1` 项。孤立点的访问序列只有它自己。

## 2. 子树为什么也是一段 Euler tour？

看以 1 为根的子树。完整序列可以分成：

```text
0 | 1  3  1 | 0  2  0
    └─ T₁ ─┘
```

中间的 `1 3 1` 从 1 出发，走完它的全部后代，最后回到 1。它本身就是子树 T₁ 的完整 Euler tour。

这不只是例子的巧合。设 v 不是根，p 是它的父亲。p—v 是这棵子树与外部之间唯一的边。DFS 沿 p→v 进入后，会先走完 v 的所有后代，再沿 v→p 离开；期间不会访问任何外部节点，离开后也不会再次进入这棵子树。

因此，若 `first(v)`、`last(v)` 分别是 v 在这条访问序列中第一次和最后一次出现的位置，则：

> 闭区间 `[first(v),last(v)]` 恰好是以 v 为根的子树的 Euler tour。

这个区间会重复记录节点，但不会遗漏子树内的节点，也不会混入子树外的节点。叶子的区间只有一项；根的区间就是整条序列。

这里的子树与 first/last 都相对于**当前选定的实际根**。根变了，子树的含义也会变。

## 3. 树的修改因此变成序列的修改

现在删除边 0—1。按上一节的性质，先分离子树 1 的游走：

```text
原序列：  0 | 1 3 1 | 0 2 0
取出：        1 3 1
剩下：    0          0 2 0
```

取出的 `1 3 1` 描述树 `1—3`。剩余两段拼接后得到 `0 0 2 0`，连接处连续两次记录了 0；去掉一个重复的边界访问，就得到另一棵树的游走 `0 2 0`。

反过来，把独立的树 `1—3` 连接到节点 0，只需在一次访问 0 后插入「前往 1、遍历整棵树、返回 0」：

```text
0 2 0   →   0 [1 3 1] 0 2 0
```

关键是：**子树内部无论有多少节点，它的游走都作为一个连续区间整体移动。** 连边与断边不需要逐个修改这些节点，只需要切开、取出和拼接序列，并处理连接处的访问记录。

这就把动态树问题转成了动态序列问题。接下来才需要选择数据结构。

## 4. 为什么引入辅助树？

数组能保存上述序列，但剪下一段再插到别处，最坏要移动线性数量的元素。我们需要一个能高效切分、拼接的序列容器。

用一棵平衡二叉树存储游走的各次访问，并规定它的**中序遍历顺序就是游走顺序**。这棵二叉树称为辅助树。实际树的一个节点可能被访问多次，因此对应多个不同的辅助节点。

例如用 `sᵢ` 表示序列位置 i 对应的辅助节点，`sᵢ:值` 中的值是那次访问到的实际节点。一种辅助树形状是：

```text
                 s₃:1
                /    \
            s₁:1      s₅:2
            /  \      /  \
         s₀:0 s₂:3 s₄:0 s₆:0
```

它的中序遍历仍然是 `0 1 3 1 0 2 0`。s₁ 与 s₃ 都记录实际节点 1，却是两个不同的辅助节点。

辅助树不模仿实际树的形状：图中辅助根记录的是 1，实际根仍是 0。辅助树中的旋转只改变序列的存储方式，只要中序顺序不变，实际树就没有改变。

还要区分两个「子树」：实际节点 1 的子树对应游走区间 `[s₁,s₃]`，它在上图中**并不恰好是一棵辅助子树**。我们通过两次切分，把这个区间分离成一棵独立的辅助树。反过来，任意辅助子树虽然总对应一个连续区间，这个区间却未必是某棵实际子树的完整游走。

于是所需原语很明确：

| 原语 | 含义 |
|---|---|
| `split(T,k)` | 将序列切成前 k 项和剩余项；k 是数量 |
| `merge(A,B)` | 按 A 在前、B 在后的顺序拼接两条不相交的序列 |
| `rank(x)` | 求辅助节点 x 当前的零起始位置 |
| `root(x)` | 沿辅助父指针找到 x 所属辅助树的根 |

每棵实际树保存一条游走，每条游走由一棵辅助树维护。只要为实际节点保留指向它某次访问的指针，就可以比较两个访问所属的辅助树，判断实际节点是否连通。

**用平衡树维护 Euler tour，便是 Euler Tour Tree。** 至此，辅助树为何存在、它存什么、需要支持哪些操作，都来自前面的子树区间性质。[MIT 6.851 Lecture 20，第 3 节](https://ocw.mit.edu/courses/6-851-advanced-data-structures-spring-2012/27804113773bfb7307eddb5157ec7aa8_MIT6_851S12_L20.pdf) 也介绍了以访问序列表示树并用平衡树维护的方式。

## 5. 实现前，选定游走的记录方式

上面的节点访问序列便于理解子树区间。不过，切分时需要合并重复的边界访问；换根后，某个节点的第一次、最后一次出现也可能改变。

本题采用同一条游走的另一种记录方式：记录**每次沿边移动**。把从 u 到 v 的移动写作 `E(u,v)`。例子中的移动序列为：

```text
E(0,1), E(1,3), E(3,1), E(1,0), E(0,2), E(2,0)
```

每条实际边恰好有两个记录，它们的端点直接标明了移动方向。删除边时，可以直接找到这两个记录，不再需要处理相邻的重复节点访问。

只有边记录还不够：孤立点没有边，也就没有记录可存。为每个实际节点 u 增加一个唯一的顶点记录 `V(u)`，表示游走在 u 处停留，不发生移动。初次构造时可以在第一次到达 u 时插入：

```text
V(0), E(0,1), V(1), E(1,3), V(3), E(3,1), E(1,0), E(0,2), V(2), E(2,0)
```

现在孤立点 u 的序列是 `[V(u)]`，每个节点也有一个不会因切口变化而消失的固定记录。保存 `vertex[u]` 指向它；对每条现存无向边，保存指向两个 E 记录的句柄。

子树区间性质仍在，只是边界写法变了：

```text
V(0), E(0,1) | V(1), E(1,3), V(3), E(3,1) | E(1,0), E(0,2), V(2), E(2,0)
                    └──── 子树 1 的游走 ────┘
```

进入边 E(0,1) 与返回边 E(1,0) **之间**的记录，恰好描述子树 1。叶子也有自己的 V 记录，因此这段序列不会为空。

从这里开始，辅助树的每个节点存一条 V 或 E 记录。后面的代码全部使用这种表示；前面的 first/last 是解释访问序列用的，不是本实现需要维护的字段。

## 6. 换根就是改变游走起点

游走最后回到起点，因此可以把它看成一个环；线性存储只是选择了一个切口。从环上的另一个节点开始走，仍会把每条有向边记录经过一次。

以上例为例，在 V(1) 之前切开：

```text
A = V(0), E(0,1)
B = V(1), E(1,3), V(3), E(3,1), E(1,0), E(0,2), V(2), E(2,0)
```

原序列是 A+B，改为 B+A 后就从 1 出发，最后沿 E(0,1) 回到 1。这是以 1 为根的游走，实际无向边没有变化。

对任一辅助记录 x，定义「将 x 移到序列开头」：

```text
rotateTo(x):
    T = root(x)
    k = rank(x)
    (A,B) = split(T,k)
    return merge(B,A)

reroot(u):
    return rotateTo(vertex[u])
```

这是循环移位，不是反转。V(u) 在旋转后仍是 u 的唯一标记，但不再保证是游走第一次到达 u 的位置。子树边界使用进入、返回的边记录，不应把 V 当成固定的 DFS 进入时间。

## 7. 推导 link、cut 与连通性查询

### link(u,v)：把两条完整游走接起来

先比较 `root(vertex[u])` 与 `root(vertex[v])`。相同则已连通，添加边会成环，直接忽略。

否则分别执行 reroot，让 U 从 u 出发并回到 u，让 W 从 v 出发并回到 v。增加两条边记录后，新的游走是：

```text
U + E(u,v) + W + E(v,u)
```

这依次表示：走完 u 的树，跨到 v，走完 v 的树，再回到 u。用三次 merge 拼接，并登记这条实际边的两个句柄即可。

### cut(u,v)：分离进入和返回之间的游走

先查找直接边 u—v；不存在就忽略。存在时，取 a=E(u,v)、b=E(v,u)，执行 `T=rotateTo(a)`。整条序列成为：

```text
a + P + b + Q
```

从 u 跨 a 到 v 之后，必须经过 b 才能返回 u 一侧，因为这条边是两侧唯一的连接。因此 P 是 v 一侧的完整游走，Q 是 u 一侧的完整游走。这正是第 2 节的子树区间性质，只是现在通过改变切口让边界位于方便的位置。

在固定例子中删除 0—1，旋到 E(0,1) 后为：

```text
E(0,1) | V(1), E(1,3), V(3), E(3,1) | E(1,0) | E(0,2), V(2), E(2,0), V(0)
   a                  P                  b                   Q
```

删除 a、b，保留 P、Q，就得到树 `1—3` 和树 `0—2`，无需改写它们内部的记录。

实现时，在任何切分之前先令 `j=rank(b)`：

```text
(a,R) = split(T,1)
(P,S) = split(R,j-1)
(b,Q) = split(S,1)
```

这里 j 是 b 在 T 中的位置，去掉开头的一项后，P 有 j-1 项。最后删除边表项、回收 a 和 b；P、Q 分别保持独立，不再合并。

### connected(u,v)：比较所属辅助树

```text
return root(vertex[u]) == root(vertex[v])
```

link 与 cut 始终保持「一棵实际树对应一棵辅助树」，所以这个比较恰好回答连通性。辅助根只是序列的标识，不必等于实际树的根，也不必存放 V 记录。

## 8. 从序列操作到复杂度

一棵 k 节点树有 k 个 V 记录、2(k-1) 个 E 记录，共 3k-2 项。整个森林只需要 `O(n)` 个活跃记录。

若用隐式 Treap 维护序列，split、merge、rank、root 的期望时间都是 `O(log n)`。每个图操作只使用常数次这样的原语，加上边表查找，所以每次操作也是期望 `O(log n)`。这里依赖随机优先级，不是单次操作的最坏情况保证。

边表可以用 map，以 `(min(u,v),max(u,v))` 为键；保存时注明两个句柄各自的方向。断边后回收两个 E 节点，重新连边时可复用，避免空间随历史操作数增长。V 节点始终保留。

## 题目与接口

初始有 n 个孤立节点，编号为 `0..n-1`。

```cpp
std::vector<int> dynamicConnectivity(
    int n, const std::vector<std::array<int, 3>>& operations);
```

| 操作 | 含义 |
|---|---|
| `{0,u,v}` | 添加无向边 u—v；若 u==v 或已经连通，则忽略 |
| `{1,u,v}` | 删除直接边 u—v；若不存在，则忽略 |
| `{2,u,v}` | 查询 u、v 是否连通，连通输出 1，否则输出 0 |

边没有方向，删除 u—v 与 v—u 相同；两点连通不代表存在直接边。只返回类型 2 的结果，不需要 main 或输入输出。同一点与自身总是连通。

`1 ≤ n ≤ 100000`，操作数不超过 200000。操作类型、节点编号均合法。没有查询返回空数组，同一个 Solution 对象的多次调用独立。目标：使用 ETT，每次操作期望 `O(log n)`，辅助空间 `O(n)`，另计返回数组。

```text
n = 3
operations = [[2,0,2], [0,0,1], [0,1,2], [2,0,2],
              [1,0,2], [2,0,2], [1,2,1], [2,0,2]]
answer = [0,1,1,0]
```

连边后形成 `0—1—2`。删除 0—2 无效，因为只有路径，没有直接边。删除 2—1 后，2 与其余节点分离。

## 实现附录：用隐式 Treap 维护游走序列

下面给出正文所需四个原语的实现。每条 V 或 E 记录对应一个 Treap 节点，保存：

```text
left, right, parent    普通辅助二叉树关系
priority              创建时生成的随机优先级，之后不变
size                  辅助子树的记录数
```

中序顺序由游走决定，不按记录的节点编号排序。「隐式」指位置由左子树大小推导，而不是把不断变化的位置存为键。优先级满足小根堆：父亲的优先级小于孩子。可用随机 64 位优先级与唯一编号组成比较键，解决碰撞。随机性决定树高；期望界不是最坏情况保证。

空节点的 `size=0`。每次改孩子后：

```text
pull(x):
    size[x] = size[left[x]] + 1 + size[right[x]]
```

节点编号与内存地址必须稳定。用整数索引最直接；若用指针，不要让存节点的 vector 扩容后使指针失效。`vertex[u]` 始终指向 V(u)，边表的句柄始终指向对应 E 记录，不能存一个以后会过期的排名。

### split(T,k) 按数量切开

约定返回 `(A,B)`：A 是前 k 个元素，B 是剩余部分。允许 `k=0` 和 `k=size[T]`。所有区间切分都使用这个**数量**约定。

先忽略父指针，只看递归逻辑：

```text
split(t,k):
    若 t 为空：返回 (空,空)
    s = size[left[t]]
    若 k <= s：
        (a,b) = split(left[t],k)
        left[t] = b
        pull(t)
        返回 (a,t)
    否则：
        (a,b) = split(right[t],k-s-1)
        right[t] = a
        pull(t)
        返回 (t,b)
```

例如 `[0,1,2,3,4]` 在 2 处切开，得到 `[0,1] | [2,3,4]`。切分只是重新连接少量二叉树边，不会逐个复制元素。

### merge(A,B) 按顺序拼接

要求 A 中所有元素都应排在 B 前面；不按记录编号比较。两棵树的节点必须互不重叠。

```text
merge(a,b):
    若一方为空：返回另一方
    若 priority[a] < priority[b]：
        right[a] = merge(right[a],b)
        pull(a)
        返回 a
    否则：
        left[b] = merge(a,left[b])
        pull(b)
        返回 b
```

优先级较小的根必须在上面，另一部分递归拼接。这样同时保持中序顺序与优先级堆性质。

本题初始化只需创建 n 棵单节点 Treap，每棵保存一个 V(u)，总计 `O(n)`。初始节点互不连通，不能把它们 merge 成一棵辅助树。

### 补全父指针后，才能按固定编号找位置

上面伪代码省略了父指针更新。实际实现约定：每次 `split` 返回的两个根、`merge` 返回的根都令 `parent=空`；把递归返回结果接为孩子时，再把孩子的 `parent` 设回当前节点。空孩子不写入。这些是普通二叉树父指针，没有 LCT 的路径父亲。

从节点 x 向父亲走到空，得到 `root(x)`。求零起始排名：

```text
rank(x):
    result = size[left[x]]
    while parent[x] 非空：
        p = parent[x]
        若 x == right[p]：result += size[left[p]] + 1
        x = p
    返回 result
```

走右边上去时，父亲和整个左子树都排在原节点前面。走左边上去时，没有新增的前驱。本题不需要翻转标记。


创建 V 或 E 节点时，可用稳定的整数索引作为句柄。E 节点回收后重用时，清空左右孩子与父指针，令 size=1，并重新生成随机优先级。不要让边表保留已回收节点的句柄。

先验证 split 后再 merge 能恢复原中序序列，再验证 rank 与父指针；这些检查通过后，正文的 reroot、link、cut 就只是在组合已验证的原语。
