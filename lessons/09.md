# 09 · Euler Tour 把 LCA 变为 RMQ

这一题把前面两类问题连起来：你已经会查询数组区间的最小值，也知道树上两点的最近公共祖先（LCA）是什么。现在要把树的遍历过程写成一个数组，使一次 LCA 查询变成一次区间最小值查询（RMQ）。

下面用同一棵树，从记录遍历开始，一步一步手算查询。

## 题目与函数接口

给定一棵以 `0` 为根的树。`parent[v]` 是节点 `v` 的父节点，`parent[0] = -1`。对于每个查询 `{u, v}`，返回两点的最近公共祖先：同时是两点祖先、并且深度最大的那个节点。一个节点也算它自己的祖先。

在 `Solution` 类中实现：

```cpp
std::vector<int>
lca(const std::vector<int> &parent,
    const std::vector<std::array<int, 2>> &queries);
```

返回数组按查询的输入顺序保存答案。只需要完成这个函数及其辅助代码，不需要编写 `main` 或处理输入输出。

- `1 ≤ n = parent.size() ≤ 200000`，`0 ≤ queries.size() ≤ 200000`。
- 输入保证是一棵合法的树；父节点编号不保证小于子节点编号。
- 每个查询都满足 `0 ≤ u, v < n`，允许 `u == v`，也允许重复查询。
- 查询列表为空时返回空数组。同一个 `Solution` 对象的多次调用应独立计算。
- 本题要求使用下面介绍的完整 Euler Tour，再对深度做 RMQ。
- 目标：预处理 `O(n log n)`，每次查询 `O(1)`。辅助空间 `O(n log n)`，另需保存返回数组。

## 第一步：先画出树和深度

使用下面这组输入：

```text
节点编号：  0  1  2  3  4
parent：  -1  0  0  1  1

        0          深度 0
       / \
      1   2        深度 1
     / \
    3   4          深度 2
```

深度是从根走到该节点需要经过的边数。于是：

| 节点 `v` | `0` | `1` | `2` | `3` | `4` |
|---|---|---|---|---|---|
| `depth[v]` | 0 | 1 | 1 | 2 | 2 |

先在图上找答案：`LCA(3, 4) = 1`，`LCA(2, 4) = 0`。接下来要看，数组查询怎样得到这两个节点。

## 第二步：把 DFS 走过的路完整记下来

从根 `0` 开始做深度优先遍历（DFS）。本例先访问左边的孩子：先遍历 `1` 的整棵子树，再遍历 `2`；在 `1` 下先访问 `3`，再访问 `4`。孩子也可以按其他顺序遍历，只要记录与实际遍历顺序一致。

这里的记录规则是：

1. 开始时记录根节点 `0`。
2. 每沿一条边走到孩子，就记录到达的孩子。
3. 孩子的整棵子树遍历完，沿边回到父节点时，再记录到达的父节点。

可以把它想成拿着笔跟随 DFS 行走：**每走过一条边，就写下现在站在哪个节点。** 返回时也算走了一条边，所以同一个节点可以被反复记录。本题把这份完整的行走记录称为 Euler Tour 序列，记作 `euler`。

逐步执行：

| 序列位置 | 发生了什么 | 这次追加的节点 | 追加后的 `euler` |
|---|---|---|---|
| 0 | 从根 `0` 开始 | `0` | `[0]` |
| 1 | 从 `0` 走到孩子 `1` | `1` | `[0, 1]` |
| 2 | 从 `1` 走到孩子 `3` | `3` | `[0, 1, 3]` |
| 3 | `3` 没有孩子，返回 `1` | `1` | `[0, 1, 3, 1]` |
| 4 | 从 `1` 走到下一个孩子 `4` | `4` | `[0, 1, 3, 1, 4]` |
| 5 | `4` 没有孩子，返回 `1` | `1` | `[0, 1, 3, 1, 4, 1]` |
| 6 | `1` 的孩子都处理完，返回 `0` | `0` | `[0, 1, 3, 1, 4, 1, 0]` |
| 7 | 从 `0` 走到下一个孩子 `2` | `2` | `[0, 1, 3, 1, 4, 1, 0, 2]` |
| 8 | `2` 没有孩子，返回 `0` | `0` | `[0, 1, 3, 1, 4, 1, 0, 2, 0]` |

现在根的所有孩子都已处理完，遍历结束。根没有父节点，不再往上走，也不记录 `-1`。

注意位置 `3` 记录的是返回后所在的节点 `1`。不是再记录一次刚离开的孩子 `3`。

### 为什么长度是 `2n - 1`？

树有 `n - 1` 条边。DFS 沿每条边向下走一次、返回时向上走一次，共移动 `2(n - 1)` 次。加上出发时记录根的那一次，总共记录：

```text
1 + 2(n - 1) = 2n - 1
```

本例有 5 个节点，所以序列长度是 9。只有根的树不需要移动，序列就是 `[0]`，长度是 1。

## 第三步：给序列配上深度，并记录首次出现的位置

每个序列位置都对应一个节点，而每个节点都有深度。把它们上下对齐：

```text
序列位置 i：       0  1  2  3  4  5  6  7  8
euler[i]：         0  1  3  1  4  1  0  2  0
depth[euler[i]]：  0  1  2  1  2  1  0  1  0
```

再用 `first[v]` 保存节点 `v` **第一次**出现在 `euler` 中的位置：

| 节点 `v` | `first[v]` | 怎样找到的 |
|---|---|---|
| `0` | 0 | `euler[0]` 首次记录根 |
| `1` | 1 | `euler[1]` 首次记录节点 `1` |
| `2` | 7 | 遍历完 `1` 的子树后，才首次到达 `2` |
| `3` | 2 | `euler[2]` 首次记录节点 `3` |
| `4` | 4 | `euler[4]` 首次记录节点 `4` |

这几个量的含义要分清。例如：

```text
first[2] = 7     节点 2 第一次出现在序列位置 7
euler[7] = 2     序列位置 7 记录的是节点 2
depth[2] = 1     节点 2 距离根有一条边
```

节点编号、序列位置和深度是三种不同的数。节点编号小，并不表示深度小。

## 第四步：跟着例子做 LCA 查询

查询 `{u, v}` 时，先找到 `first[u]` 和 `first[v]`，把较小者作为左端点 `l`，较大者作为右端点 `r`。然后在闭区间 `euler[l..r]` 中，找到**深度最小的节点**并返回它的节点编号。

### 例 1：兄弟节点 `3` 和 `4`

1. 找位置：`first[3] = 2`，`first[4] = 4`。
2. 取闭区间 `[2, 4]`，两个端点都包含。
3. 查看这一段的节点和深度：

```text
序列位置：  2  3  4
节点：      3  1  4
深度：      2  1  2
               ↑
          最小深度在这里
```

这段记录对应的移动是 `3 → 1 → 4`。深度最小的节点是 `1`，所以返回 `1`。

这里最小深度也恰好是数字 `1`，但答案的含义是**节点编号**。下面一例能更清楚地区分两者。

### 例 2：不同分支上的节点 `2` 和 `4`

1. 找位置：`first[2] = 7`，`first[4] = 4`。
2. 输入中 `2` 在前，但它在遍历中出现得更晚，所以交换两个位置，查询 `[4, 7]`。
3. 查看这一段：

```text
序列位置：  4  5  6  7
节点：      4  1  0  2
深度：      2  1  0  1
                  ↑
             最小深度在这里
```

从节点 `4` 所在的分支去往节点 `2`，必须先回到根 `0`。因此答案是节点 `0`。

这次 RMQ 找到的**序列位置是 `6`**，该位置记录的**节点是 `euler[6] = 0`**。返回 `0`，不要把序列位置 `6` 当作答案。

### 例 3：一个节点本来就是另一个的祖先

查询 `LCA(1, 4)`：`first[1] = 1`，`first[4] = 4`，取区间 `[1, 4]`。

```text
序列位置：  1  2  3  4
节点：      1  3  1  4
深度：      1  2  1  2
            ↑     ↑
           两处都是最小深度
```

DFS 在到达 `4` 之前，先去过 `3`，所以这一段记录里有一次绕路；它不一定等于两点间的简单路径。

但绕路没有走到节点 `1` 的上方。最小深度仍然是节点 `1` 的深度。位置 `1` 和 `3` 都达到这个最小值，而且记录的都是同一个节点 `1`，选任意一个位置都得到答案 `1`。

### 例 4：查询同一个节点

查询 `LCA(3, 3)`：两个首次出现位置都是 `2`，区间 `[2, 2]` 只有节点 `3`。

```text
序列位置：  2
节点：      3
深度：      2
```

答案是节点 `3`，不是最小深度 `2`。这也说明，RMQ 只保存最小深度的数值还不够，还需要能找到对应的节点。

因此，上面四组查询的完整输入输出为：

```text
parent  = [-1, 0, 0, 1, 1]
queries = [[3, 4], [2, 4], [1, 4], [3, 3]]
answer  = [1, 0, 1, 3]
```

## 第五步：为什么区间中深度最小的节点就是 LCA？

先假设 `u` 比 `v` 更早被访问，记它们的 LCA 为 `w`。

可以结合刚才的例子看两件事：

1. **从首次到达 `u` 到首次到达 `v`，这段记录一定包含 `w`。** 如果 `u` 就是 `w`，区间左端已经包含它；否则两点位于 `w` 的不同孩子子树中，DFS 必须先从 `u` 所在分支返回 `w`，才能进入 `v` 所在分支。返回时的记录就把 `w` 留在了序列中。
2. **这段记录不会走到 `w` 的父节点。** DFS 会先遍历完 `w` 的整棵子树，才返回 `w` 的父节点。`v` 还在这棵子树里，所以首次到达 `v` 之前，不会离开这棵子树。

两件事合起来：区间里出现了 `w`，并且所有出现的节点都在 `w` 的子树中。`w` 的深度最小，它的任何后代都更深，因此 RMQ 找到的节点就是 `w`。

即使 `w` 在区间中出现多次，也只是同一个节点的多个记录位置，不影响答案。

## 第六步：为什么每个节点只记录一次不够？

仍然按刚才的顺序 DFS，但只记录第一次到达每个节点，得到常见的 DFS 先序序列：

```text
节点：  0  1  3  4  2
深度：  0  1  2  2  1
```

再试 `LCA(3, 4)`。两个节点之间只剩下：

```text
节点：  3  4
深度：  2  2
```

真正的 LCA 是节点 `1`，但它根本不在这个区间里。无论怎样取最小值，都不可能从这个区间中选出 `1`。

完整 Euler Tour 在从 `3` 返回时补上了一次 `1`：

```text
只记首次到达：  3      4
完整行走记录：  3 → 1 → 4
                   ↑
             返回时记录的祖先
```

所以，返回父节点时的记录是这次归约成立的关键。每点只记录一次的 DFS 序可以用于把子树映射为连续区间，但不能直接套用这里的“两个首次位置之间取最小深度”的方法。

## 实现时需要维护什么？

可以先完成遍历并手算核对，再接上 RMQ。需要的三个数组是：

| 数组 | 下标表示什么 | 保存什么 |
|---|---|---|
| `depth[v]` | 节点编号 | 节点到根的边数 |
| `first[v]` | 节点编号 | 节点首次出现在 `euler` 中的位置 |
| `euler[i]` | 遍历序列中的位置 | 这次记录的节点编号 |

在本例中，它们应当是：

```text
depth = [0, 1, 1, 2, 2]
first = [0, 1, 7, 2, 4]
euler = [0, 1, 3, 1, 4, 1, 0, 2, 0]
```

下面的提示分别对应遍历和区间查询，可以按实现进度展开。

<details>
<summary>提示 1：怎样用显式栈保留“从孩子返回”的时机？</summary>

先根据 `parent` 建立每个节点的孩子列表。根深度为 `0`，进入孩子时令孩子深度等于父节点深度加 `1`。

原树可能是一条很长的链，所以不要依赖同样深度的函数递归。显式栈可以模拟递归调用：每个栈帧保存当前节点，以及“下一个要处理的孩子”的位置。

- 初始时将根入栈，同时记录根。
- 栈顶还有没处理的孩子时，推进孩子位置，把那个孩子入栈并记录它。
- 栈顶的孩子都处理完时，将它出栈。如果栈仍然非空，新栈顶就是返回后所在的父节点，追加记录这个父节点。
- 根出栈后，栈为空，遍历结束，不追加节点。

节点第一次入栈、准备追加到 `euler` 时，用当时的 `euler.size()` 记录 `first`。返回时追加的是已有节点，不覆盖它的 `first`。

</details>

<details>
<summary>提示 2：怎样复用第 02 题的稀疏表？</summary>

第 02 题在数组区间内取最小值。这里比较的是 `depth[euler[i]]`，但最后需要返回节点，所以可以让稀疏表保存**最小深度对应的序列位置**。

例如，比较两个候选序列位置 `a` 和 `b`：先比较 `depth[euler[a]]` 与 `depth[euler[b]]`，留下深度较小者的位置；相等时固定选较小的位置也可以。

设 `best[j][i]` 保存从序列位置 `i` 开始、长度为 `2^j` 的区间中的最佳位置：

- 长度为 1 时，`best[0][i] = i`。
- 更长区间由前后两个半区间合并，比较它们保存的候选位置。
- 只建立没有越过 `euler` 末尾的有效区间。

查询闭区间 `[l, r]` 时，和第 02 题一样，用两块长度为 `2^k` 的区间覆盖，其中 `k = floor(log2(r - l + 1))`。比较两块各自保存的最佳位置，得到位置 `p`，返回 `euler[p]`。

用 `LCA(3, 4)` 再手算一次：

```text
要查询的序列区间： [2, 4]，长度 3
使用的两块：       [2, 3] 和 [3, 4]，长度都为 2
第一块的节点：     [3, 1]，最佳位置为 3
第二块的节点：     [1, 4]，最佳位置也为 3
最终返回：         euler[3] = 1
```

两块可以重叠，因为重复考虑一个位置不会改变最小深度的选择。为保证每次查询 `O(1)`，区间长度的向下取整对数也要通过预处理或固定宽度整数的位操作取得，而不是每次循环计算。

</details>

## 复杂度与手动检查

Euler Tour 共 `2n - 1` 项，构造它需要 `O(n)` 时间和空间。在它上面建立稀疏表需要 `O(n log n)` 时间和空间；每次 LCA 查询只做两次首次位置读取和一次 RMQ，因此是 `O(1)`。加上 `q` 次查询，总时间为 `O(n log n + q)`。

编辑 [exercises/09.cppm](../exercises/09.cppm) 时，可以按这个顺序检查：

1. 先用本例核对 `depth`、`first` 和完整 `euler`，尤其检查从孩子返回时是否记录了父节点。
2. 手算上面的四组查询，分别覆盖兄弟、不同分支、祖先与后代、相同节点。
3. 检查单节点树：`euler = [0]`，查询 `{0, 0}` 返回 `0`。
4. 检查父编号大于子编号的树，以及长链、星形树、空查询列表和多次函数调用。

准备好后，你可以在项目的 Nix 开发环境中运行：

```bash
./judge 09
```
