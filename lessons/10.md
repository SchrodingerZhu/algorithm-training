# 10 · Cartesian Tree：把 RMQ 变为 LCA

给定一个数组，要反复查询某个区间中最小元素的位置。数组本身没有树结构；这一题要先根据数组构造一棵二叉树，再把区间查询转为树上的最近公共祖先查询。

下面从输入输出开始，解释这棵树是什么、怎样构造，以及为什么树上的答案就是数组中的答案。

## 题目与函数接口

给定一个非空数组 `values` 和若干查询 `queries`。每个查询 `{l, r}` 表示闭区间 `[l, r]`，即包含 `values[l]` 到 `values[r]` 的所有元素。

对每个查询，返回区间中**最小值所在的下标**。如果最小值出现多次，返回这些位置中最小的下标。这种查询称为区间最小值查询（Range Minimum Query，RMQ）；强调返回位置时，称为 `argmin`。本题对多个位置取得相同最小值的情况，明确规定选择下标最小的位置。

也就是说，先确定区间内的最小值 `m`，再从所有满足 `l ≤ i ≤ r` 且 `values[i] == m` 的下标 `i` 中，返回最小的那个。这里的“最小值”是数组元素的值，返回的答案则是一个下标。

在 `Solution` 类中实现：

```cpp
std::vector<int>
argMin(const std::vector<long long> &values,
       const std::vector<std::array<int, 2>> &queries);
```

返回数组按查询的输入顺序保存答案。只需要完成这个函数及其辅助代码，不需要编写 `main` 或处理输入输出。

- `1 ≤ n = values.size() ≤ 200000`，`0 ≤ queries.size() ≤ 200000`。
- `-10⁹ ≤ values[i] ≤ 10⁹`，允许负数和重复值。
- 下标从 `0` 开始；每个查询保证满足 `0 ≤ l ≤ r < n`。
- 数组在所有查询期间保持不变，没有修改操作。
- 查询列表为空时返回空数组。同一个 `Solution` 对象的多次调用应独立计算。
- 本题要求先构造最小 Cartesian Tree，再通过 LCA 回答查询。
- 目标：建树 `O(n)`，LCA 预处理 `O(n log n)`，每次查询 `O(log n)` 或 `O(1)`，辅助空间 `O(n log n)`。

例如：

```text
values  = [3, 1, 1, 2]
queries = [[0, 3], [2, 3], [0, 0]]
answer  = [1, 2, 0]
```

查询 `[0, 3]` 时，最小值 `1` 出现在下标 `1` 和 `2`，所以返回 `1`。查询 `[2, 3]` 时返回 `2`，因为它是该区间内最小值的位置。查询 `[0, 0]` 只有一个元素，返回其下标 `0`，而不是它的值 `3`。

## 第一步：什么是 Cartesian Tree？

Cartesian Tree（笛卡尔树）是把数组的每个位置变成一个节点后构造出的**二叉树**：每个节点最多有一个左孩子和一个右孩子。节点编号就是数组下标，节点 `i` 携带的值是 `values[i]`。

本题使用的最小笛卡尔树同时满足两个条件。

### 条件 1：中序遍历按数组下标递增

二叉树的中序遍历顺序是：先遍历左子树，再访问当前节点，最后遍历右子树。对这棵树做中序遍历，得到的节点编号必须恰好是：

```text
0, 1, 2, ..., n - 1
```

因此，节点 `i` 的左子树里全是小于 `i` 的下标，右子树里全是大于 `i` 的下标。每棵子树也对应数组中的一个连续区间，因为中序遍历会连续输出整棵子树。

### 条件 2：父节点的优先级小于孩子

给节点 `i` 定义比较用的二元组：

```text
key(i) = (values[i], i)
```

比较两个二元组时，先比较值；值相同，再比较下标。每条父子边都要求父节点的 `key` 小于孩子的 `key`。这就是这里的最小堆性质。

沿着父子边往下走，`key` 严格变大，所以每棵子树的根都是该子树中值最小、并列时下标最小的节点。用下标打破平局，正好对应题目要求：最小值出现多次时，返回这些位置中最小的下标。

这两个条件各自负责一件事：中序顺序保留数组位置关系，堆性质保留最小值关系。

### 从定义直接得到一种建树方法

对于某个数组区间 `[L, R]`：

1. 找到区间内的最小值；如果它出现在多个位置，选择其中下标最小的位置。将选中的下标记为 `m`，把节点 `m` 作为根。
2. 用区间 `[L, m - 1]` 递归构造它的左子树。
3. 用区间 `[m + 1, R]` 递归构造它的右子树。
4. 空区间没有节点；只有一个元素的区间形成叶子节点。

这样既满足中序顺序，也满足堆性质。反过来，两个条件也迫使根及左右子树按这个规则选择，因此平局规则确定后，整棵树唯一确定。

这是理解树形的方法。如果每次都扫描区间找最小值，递增数组会导致扫描长度依次为 `n, n-1, ..., 1`，总时间达到 `O(n²)`。后面会用单调栈在 `O(n)` 时间内构造同一棵树。

## 第二步：手算一棵树

接下来统一使用这个包含重复最小值的例子：

```text
下标：     0  1  2  3  4
values：  [3, 1, 4, 1, 2]
```

全局最小值是 `1`，出现在下标 `1` 和 `3`，两者中较小的下标是 `1`，所以根是节点 `1`。左边只剩节点 `0`。右边区间 `[2, 4]` 的最小值在下标 `3`，所以右子树的根是节点 `3`。

用 `下标:值` 标注节点，得到：

```text
          1:1
         /   \
       0:3   3:1
             / \
           2:4 4:2
```

检查中序遍历：左子树输出 `0`，根输出 `1`，右子树输出 `2, 3, 4`，合起来正好是 `0, 1, 2, 3, 4`。

检查堆性质：根的 `(1, 1)` 小于右孩子的 `(1, 3)`，即使两者的数组值相同，平局规则仍然满足。其余父子边也都满足父节点的值更小。

注意：**根由数组内容决定，不一定是节点 `0`。** 本例根是 `1`；严格递减数组的根则是最后一个节点。

## 第三步：为什么查询变成了 LCA？

在有根树中，一个节点向上经过父节点到根所遇到的节点都叫它的祖先；这里也把节点自身算作祖先。两个节点的最近公共祖先（Lowest Common Ancestor，LCA）是它们共同祖先中深度最大的那个，即离根最远的共同祖先。根的深度为 `0`，每向下一条边，深度加 `1`。

本题的结论是：

```text
区间 [l, r] 的查询答案 = 笛卡尔树上的 LCA(l, r)
```

这里把区间两端的**下标**当作节点编号。LCA 返回的节点编号本身就是答案，不需要再把它换成数组值。

在上面的树中：

| 查询区间 | 区间内的值 | 两端节点的 LCA | 返回下标 |
|---|---|---|---|
| `[0, 4]` | `[3, 1, 4, 1, 2]` | `LCA(0, 4) = 1` | `1` |
| `[2, 4]` | `[4, 1, 2]` | `LCA(2, 4) = 3` | `3` |
| `[1, 3]` | `[1, 4, 1]` | `LCA(1, 3) = 1` | `1` |
| `[2, 2]` | `[4]` | `LCA(2, 2) = 2` | `2` |

### 为什么结论成立？

令 `w = LCA(l, r)`，分三步看。

1. **`w` 的子树包含整个区间 `[l, r]`。** 它包含节点 `l` 和 `r`，而子树的中序下标形成连续区间，所以也包含两者之间的所有下标。
2. **`w` 自己的下标也在 `[l, r]` 内。** 如果 `w < l`，那么 `l` 和 `r` 都在 `w` 的右子树中，它们就有一个更深的共同祖先，与 `w` 是 LCA 矛盾。`w > r` 时同理，两点都会落在左子树中。
3. **`w` 的 `key` 是区间内最小的。** 根据堆性质，`w` 的 `key` 小于它所有后代的 `key`；区间内节点都是其后代或它自身，而它又在区间内，所以它就是所求位置。

`key` 同时比较值和下标，因此这段论证也包括最小值出现多次时选择最小下标的规则。

这里并不要求 `w` 的子树**恰好等于**查询区间。例如查询 `[1, 3]` 的 LCA 是根 `1`，但根的子树覆盖 `[0, 4]`。证明只需要子树包含查询区间，并且 `w` 本身在查询区间内。

## 第四步：怎样用单调栈在线性时间内建树？

按下标从左到右处理数组，用栈保存已经建好的树从根出发、不断走向右孩子所经过的节点。栈底是当前根，栈顶是最新插入的节点。

这些节点的下标递增，值不递减；若值相等，较早的下标排在前面，因此它们的 `key` 严格递增。这样的栈称为单调栈。

当新节点 `i` 到来时，它比所有已处理节点都靠右，所以新的连接只会改变这条最右路径。它的值决定它能作为哪些节点的父节点。

### 每次插入要做的事

可以用 `left[i]`、`right[i]` 保存左右孩子，初始都为 `-1`，表示没有孩子。对每个新节点 `i`：

1. 令 `last = -1`。
2. 只要栈非空且 `values[栈顶] > values[i]`，就弹出栈顶，并将刚弹出的节点记为 `last`。
3. 如果弹栈后栈仍非空，把 `i` 设为剩余栈顶的右孩子。
4. 如果 `last != -1`，把 `last` 设为 `i` 的左孩子。
5. 将 `i` 入栈。

全部处理完后，栈底就是整棵树的根。若同时维护初始全为 `-1` 的 `parent` 数组，第 3 步更新 `parent[i]`，第 4 步更新 `parent[last]`；其余子树内部的父子关系保留。

### 为什么只接住最后弹出的节点？

弹栈并不是删除树中的节点，而是把它们移出最右路径。若连续弹出多个节点，最后弹出的节点是这些节点中最靠近原根的那个，它的子树已经包含先前弹出的节点。把它作为新节点的左孩子，就接住了整棵子树。

例如已有值 `[2, 4, 5]`，树是一条右链，栈为 `[0, 1, 2]`。插入值 `1` 的节点 `3` 时，依次弹出 `2, 1, 0`，最后的 `last` 是 `0`。令 `left[3] = 0`，原来的 `0 → 1 → 2` 右链仍保留，所有旧节点都成为新根 `3` 的左子树。

如果弹栈后还剩节点 `p`，那么被弹出的那棵子树原本就是 `p` 的右子树。现在改为 `p` 的右孩子是 `i`，而 `i` 的左孩子接住旧子树。旧节点的下标都小于 `i`，被弹出的节点又都比 `i` 的值大，所以中序顺序与堆性质都得到保留。

### 为什么相等时不能弹栈？

新节点的下标一定更大。值相等时，旧节点的 `key` 更小，应当留在上方。因此条件是严格的 `>`，不是 `>=`。

例如数组 `[1, 1]` 必须让节点 `0` 做根、节点 `1` 做右孩子，才能使 `[0, 1]` 的答案为 `0`。若相等时也弹栈，就会让节点 `1` 成为根，错误地返回较大的下标 `1`。

### 按主例逐步执行

仍使用 `values = [3, 1, 4, 1, 2]`。表中的栈保存的是下标，顺序从栈底到栈顶。

| 新节点 `i` | 值 | 弹出的节点 | 新的连接 | 插入后的栈 |
|---|---|---|---|---|
| `0` | `3` | 无 | 单节点树，根为 `0` | `[0]` |
| `1` | `1` | `0` | `left[1] = 0`，新根为 `1` | `[1]` |
| `2` | `4` | 无 | `right[1] = 2` | `[1, 2]` |
| `3` | `1` | `2` | `right[1] = 3`，`left[3] = 2` | `[1, 3]` |
| `4` | `2` | 无 | `right[3] = 4` | `[1, 3, 4]` |

插入节点 `3` 时，节点 `1` 的值也等于 `1`，所以它不被弹出。节点 `2` 则从节点 `1` 的右孩子，变成节点 `3` 的左孩子。最后再插入节点 `4`，树形正是前面手算的结果。

最终数组应为：

```text
节点 i：   0   1   2   3   4
left：    -1   0  -1   2  -1
right：   -1   3  -1   4  -1
parent：   1  -1   3   1   3
root = 1
```

每个节点只入栈一次，最多出栈一次，所以所有 `while` 循环合起来只弹出 `O(n)` 次，建树总时间为 `O(n)`，空间为 `O(n)`。

## 第五步：建树之后怎样回答 LCA？

一种直接可用的方法是二进制提升，也叫倍增。它预先记录“向上走 `1, 2, 4, 8, ...` 条边会到哪里”，使查询时能一次跳过很多层。

### 预处理深度和祖先表

从建树得到的实际根出发，遍历左右孩子，计算 `depth[v]` 和每个节点的父节点。可以使用显式栈或队列；递增、递减或全相等的数组都可能形成长度为 `n` 的链，不应依赖同样深度的函数递归。

定义：

```text
up[k][v] = 从节点 v 向上走 2^k 条边后到达的祖先
```

对祖先表采用“到达根后继续向上仍停在根”的约定，令 `up[0][root] = root`；其他节点的 `up[0][v]` 为实际父节点。建树数组中的 `parent[root]` 仍可保留为 `-1`，不要用它直接访问祖先表。

更高层通过两次较短的跳跃得到：

```text
up[k][v] = up[k - 1][up[k - 1][v]]
```

先填完所有节点的第 `0` 层，再逐层填写。保存到 `k = floor(log2(n))` 即足够，也覆盖 `n = 1` 时的第 `0` 层。

### 一次 LCA 查询

设要找节点 `u` 和 `v` 的 LCA：

1. 把较深的节点按深度差的二进制位向上跳，使两点深度相同。例如差 `5 = 4 + 1`，就跳一次 `2²` 层、一次 `2⁰` 层。
2. 如果两点已经相同，这个节点就是答案。
3. 否则从最大的 `k` 到 `0` 检查：如果 `up[k][u] != up[k][v]`，就让两点同时跳到各自的这个祖先。
4. 检查完后，两点位于 LCA 下方一层，返回 `up[0][u]`。

第 3 步只在目标祖先不同时跳跃：两点在同一深度，如果跳到的位置仍不同，说明还没到共同祖先，可以安全上跳；若目标相同，则这一步可能到达或越过 LCA，先尝试更短的跳跃。

例如主例的查询 `[2, 4]` 中，节点 `2` 和 `4` 都在深度 `2`，它们的父节点都是 `3`，所以答案是 `3`。查询 `[0, 4]` 时，先把节点 `4` 提升到节点 `3`，与节点 `0` 同处深度 `1`，再返回它们的共同父节点 `1`。

祖先表的预处理时间和空间均为 `O(n log n)`，每次查询为 `O(log n)`。

<details>
<summary>另一种选择：Euler Tour 加稀疏表，把查询降到 O(1)</summary>

从实际根出发做深度优先遍历（DFS），即先遍历完一个孩子的整棵子树，再处理下一个孩子。进入节点时记录它，每从一个孩子返回时再记录当前节点，得到长度为 `2n - 1` 的完整行走记录，称为 Euler Tour。保存每个节点的深度及其首次出现在序列中的位置 `first[v]`。

查询两点的 LCA 时，在它们两个首次位置之间寻找深度最小的节点。原因是从一端首次到达另一端之前，一定经过它们的 LCA，又不会离开这个 LCA 的子树，因此最小深度对应的就是 LCA。

可对序列建立稀疏表：第 `k` 层保存每个长度为 `2^k` 的区间里深度最小的节点，由两个长度为 `2^(k-1)` 的半区间合并。查询长度为 `m` 的区间时，取 `k = floor(log2(m))`，比较从左端开始和在右端结束的两个长度为 `2^k` 的区间答案即可。两块可以重叠，因为重复比较不影响最小值。对数用预处理或固定宽度整数的位操作取得。

该方法预处理时间和空间均为 `O(n log n)`，查询为 `O(1)`。实现时保存的是最小深度对应的节点，最终返回它的编号；不要返回深度或 Euler Tour 中的位置。遍历同样要避免深链递归。

</details>

## 复杂度与动手检查

使用倍增时，总时间为 `O(n log n + q log n)`；使用 Euler Tour 加稀疏表时，总时间为 `O(n log n + q)`。两种方法的辅助空间都是 `O(n log n)`，另需 `O(q)` 空间保存返回数组。

编辑 [exercises/10.cppm](../exercises/10.cppm) 时，可以分两步完成：先只建树，核对主例的根与左右孩子；再接上 LCA，核对区间查询结果。

重点检查：

1. 单元素数组：唯一的查询 `[0, 0]` 返回 `0`。
2. 全相等数组：任意查询 `[l, r]` 都应返回 `l`，检查弹栈条件是否为严格的 `>`。
3. 严格递增数组：树是一条右链，区间答案为 `l`。
4. 严格递减数组：树是一条左链，根为 `n - 1`，区间答案为 `r`。
5. 负数与重复最小值，例如 `[-2, 5, -2]`：`[0, 2]` 返回 `0`，`[1, 2]` 返回 `2`。
6. 空查询列表、整个数组的查询，以及同一个 `Solution` 对象的多次调用。

```bash

```
