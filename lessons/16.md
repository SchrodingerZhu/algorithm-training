# 16 · LCT 前置：隐式 Splay 与区间翻转

前几题的数组位置一直固定。这一题会翻转一段序列，因此某个元素的位置会随着操作改变。我们需要一种结构，既能按当前排名找到元素，又能把整个区间的顺序反过来。

隐式 Splay 用二叉树的中序遍历表示序列。它通过旋转改变树形，通过子树大小定位排名，通过懒标记推迟翻转。本题先把这些操作讲清楚，为后续的 Link-Cut Tree 做准备。

## 题目与函数接口

给定非空初始序列 `values`，按输入顺序处理：

| 操作 | 含义 | 是否产生答案 |
|---|---|---|
| `{0, l, r}` | 翻转当前序列的闭区间 `[l, r]` | 否 |
| `{1, l, r}` | 查询当前序列闭区间 `[l, r]` 的元素和 | 是 |

下标始终指**操作发生时的序列位置**，不是元素在初始数组中的编号。翻转会影响后续操作所指向的元素。

在 `Solution` 类中实现：

```cpp
std::vector<long long>
reverseSum(const std::vector<long long> &values,
           const std::vector<std::array<int, 3>> &operations);
```

返回数组只保存查询答案，顺序与查询出现的顺序一致。不需要编写 `main` 或处理输入输出。

- `1 ≤ n = values.size() ≤ 100000`，`0 ≤ operations.size() ≤ 100000`。
- `-10⁹ ≤ values[i] ≤ 10⁹`，允许负数与重复值。
- 每次操作都保证 `0 ≤ l ≤ r < n`，序列长度始终不变。
- 要求使用隐式 Splay，每次操作均摊 `O(log n)`，辅助空间 `O(n)`。
- 没有查询时返回空数组；同一个 `Solution` 对象的多次调用应独立计算。

## 手算：位置会变，元素的值不会变

```text
values     = [1, 2, 3, 4]
operations = [[0, 0, 2], [1, 0, 1], [0, 1, 3], [1, 0, 1]]
answer     = [5, 7]
```

| 操作 | 执行后的序列 | 查询结果 |
|---|---|---|
| 翻转 `[0, 2]` | `[3, 2, 1, 4]` | 不输出 |
| 查询 `[0, 1]` | `[3, 2, 1, 4]` | `3 + 2 = 5` |
| 翻转 `[1, 3]` | `[3, 4, 1, 2]` | 不输出 |
| 查询 `[0, 1]` | `[3, 4, 1, 2]` | `3 + 4 = 7` |

第二次翻转处理的是当前的 `[2, 1, 4]`，不是初始数组中同位置的 `[2, 3, 4]`。

## 第一步：用中序遍历表示序列

普通二叉搜索树按键值决定左右顺序；本题不按元素值排序，而是约定：**树的中序遍历顺序就是当前序列顺序**。值相同的两个元素仍然是不同节点，各占一个序列位置。

为每个真实节点维护：

| 字段 | 含义 |
|---|---|
| `left, right, parent` | 左右孩子与父节点 |
| `val` | 该节点存放的元素值 |
| `size` | 以它为根的子树节点数 |
| `sum` | 以它为根的子树元素和 |
| `rev` | 是否还有一次翻转需要传给孩子 |

可以用内部编号 `0` 表示空节点，真实节点从 `1` 开始。空节点的 `size` 和 `sum` 都为 `0`，不对空节点执行翻转。

重新聚合一个节点 `x` 时，使用：

```text
size[x] = size[left[x]] + 1 + size[right[x]]
sum[x]  = sum[left[x]] + val[x] + sum[right[x]]
```

这通常封装为 `pull(x)`。这里的 `size` 是辅助二叉树的子树大小，不是前几题中固定原树的子树大小。

### 如何找到当前排名为 k 的元素？

暂时把整棵二叉树的中序排名定义为从 `0` 开始。到达节点 `x` 时，先下传它的翻转标记，再令 `s = size[left[x]]`：

- 如果 `k < s`，目标在左子树，继续向左找。
- 如果 `k == s`，当前节点就是目标。
- 如果 `k > s`，目标在右子树，令 `k -= s + 1` 后继续向右找。

左子树中的元素都排在当前节点之前，所以只看子树大小就能确定方向，无需比较 `val`。每次按排名查找后，还要配合下面的 Splay 操作调整树形，不能一直在可能退化的树上只查找而不调整。

## 第二步：旋转改变树形，但保留中序顺序

以节点 `x` 是父节点 `p` 的左孩子为例，一次右旋如下，其中 `A, B, C` 表示可能为空的子树：

```text
        p                  x
       / \                / \
      x   C      →       A   p
     / \                    / \
    A   B                  B   C
```

旋转前后的中序顺序都是 `A, x, B, p, C`，所以序列没有改变。`x` 升到 `p` 原来的位置，子树 `B` 从 `x` 的右侧转接到 `p` 的左侧。

实现 `rotate(x)` 时，需要维护原祖父与新子树根的连接、`x` 和 `p` 的父指针，以及中间子树 `B` 的父指针。若原来 `p` 就是整棵树的根，还要更新根编号。左旋是完全对称的情况。

旋转后先 `pull(p)`，再 `pull(x)`：旧父节点已经下降，应先算好它的新统计，才能用于计算新父节点的统计。

### Splay 怎样把节点提到指定位置？

`splay(x, goal)` 把 `x` 旋到父节点为 `goal` 的位置；`goal = 0` 表示把它旋到整棵树的根。每轮观察 `x`、父节点 `p` 和祖父 `g`：

1. 如果 `p` 的父节点已经是 `goal`，只旋转 `x` 一次。
2. 否则，若 `x` 与 `p` 都是各自父亲的左孩子，或都是右孩子，先旋转 `p`，再旋转 `x`，称为同向双旋。
3. 否则先旋转 `x`，再旋转 `x`，称为异向双旋。

重复直到 `parent[x] == goal`。两种双旋都保留中序顺序；它们是 Splay 获得均摊复杂度保证的标准调整方式，不能随意替换为一路单旋。

## 第三步：怎样延迟执行整段翻转？

一棵子树表示一段连续序列。要反转这段序列，需要交换左右部分，同时递归反转这两部分。可以先只对根节点 `x` 执行：

```text
交换 left[x] 和 right[x]
rev[x] ^= 1
```

这记为 `applyReverse(x)`。翻转不会改变元素数量或元素和，所以 `size[x]` 和 `sum[x]` 保持不变。

`rev[x]` 表示孩子内部的反转尚未执行。以后需要下行时，`push(x)` 对左右孩子分别调用 `applyReverse`，再清除 `rev[x]`。两次反转恢复原顺序，所以标记使用异或：已有一次待处理翻转时，再来一次就抵消。

### 为什么旋转前也要下传？

旋转会改变子树成员。如果一个旧翻转标记还没有传下去就先改变父子关系，它后续可能作用到错误的一组元素上；未处理的方向也可能使双旋类型判断出错。

因此，在开始 Splay 前，收集从 `x` 到旋转边界的祖先，按从上到下的顺序执行 `push`，再旋转。带非空 `goal` 时也要确保边界节点的标记已经下传。排名查找则在每次决定向左还是向右之前下传当前节点。

## 第四步：用两个哨兵把目标区间单独取出来

在序列前后各加入一个哨兵节点，它们不属于用户数组，值可设为 `0`。整棵树的中序顺序成为：

```text
左哨兵，values[0]，values[1]，...，values[n-1]，右哨兵
```

哨兵是真实的树节点，因此参与 `size` 计数。按包含哨兵的整棵树进行零起始排名时，左哨兵排名为 `0`，用户位置 `i` 的当前元素排名为 `i + 1`，右哨兵排名为 `n + 1`。

对用户闭区间 `[l, r]`，边界节点的排名是：

```text
区间左侧紧邻节点：排名 l
区间右侧紧邻节点：排名 r + 2
```

例如整个数组区间 `[0, n-1]` 的两个边界恰好就是左右哨兵。

依次执行：

1. 找到排名为 `l` 的节点 `a`，将它 Splay 到根。
2. 按整棵树的排名找到 `r + 2` 对应的节点 `b`，将它 Splay 到父节点为 `a` 的位置。
3. 此时 `b` 是 `a` 的右孩子，而 `b` 的左子树恰好表示目标区间。

第二次查找要允许只定位节点，然后调用 `splay(b, a)`；不要让查找函数自动把 `b` 旋到整棵树的根。

### 为什么中间子树恰好是目标区间？

旋转保持中序顺序。`a` 位于目标区间之前，`b` 位于目标区间之后；把它们放成根和根的右孩子后，所有顺序上介于 `a` 与 `b` 之间的节点，都只能在 `b` 的左子树里。其他节点则在 `a` 的左侧或 `b` 的右侧。

所以查询只需读取 `sum[left[b]]`，翻转只需对 `left[b]` 应用翻转标记。完成后可依次 `pull(b)`、`pull(a)`，保持边界节点的统计完整。哨兵始终在目标子树之外，不会成为查询元素。

## 初始化与均摊复杂度

可以按包含哨兵的序列取中点建树，递归建立左右半段，再从下往上 `pull`。这样初始建树为 `O(n)`，递归深度为 `O(log n)`。这与在任意退化树上进行深度为 `n` 的递归不同。

一次 Splay 可能旋转很多次，因此这里的 `O(log n)` 是**均摊**保证，不是每个操作的最坏情况保证。标准 Splay 分析用子树大小的对数衡量树形变化，说明一串访问和旋转的总成本可被控制；区间操作只组合常数次排名访问与 Splay，所以总时间为 `O((n + m) log n)`，其中 `m` 为操作数，空间为 `O(n)`。

`sum` 使用 `long long`，因为最多 100000 个绝对值为 `10⁹` 的元素求和会超过 32 位整数范围。翻转不改变值，因此不需要给元素重新赋权。

## 检查与运行

编辑 [exercises/16.cppm](../exercises/16.cppm) 时，先实现 `pull`、旋转和 Splay，再验证排名查找，最后加入懒翻转和区间隔离。重点检查：

1. 单元素区间翻转后保持不变，查询返回该元素。
2. 整段翻转、前缀翻转和后缀翻转，确保哨兵位置正确。
3. 同一区间连续翻转两次，序列应恢复原状。
4. 两个部分重叠的区间连续翻转，后续操作必须使用当前位置。
5. 负数、重复值、空操作列表和同一对象的多次调用。
6. 用普通数组逐步反转小样例，核对每次查询及当前序列，而不只核对总和；翻转方向错误可能仍保留全序列总和。
