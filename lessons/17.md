# 17 · LCT：动态森林连通性

前面的树链剖分依赖固定的树边。现在允许增加和删除边，原先算好的子树大小、重儿子和链头可能大范围失效，不能在每次操作后重新剖分整棵树。

Link-Cut Tree（LCT）用一组辅助 Splay 表示森林中的若干路径，并在访问节点时调整这些路径。本题先处理连通性：两点是否在同一棵树中，以及怎样在保持森林结构的前提下连边、断边。

## 题目与函数接口

初始有 `n` 个孤立节点，编号为 `0` 到 `n - 1`，没有任何边。按输入顺序执行：

| 操作 | 含义 | 是否产生答案 |
|---|---|---|
| `{0, u, v}` | 尝试添加无向边 `u—v` | 否 |
| `{1, u, v}` | 尝试删除无向边 `u—v` | 否 |
| `{2, u, v}` | 查询 `u` 与 `v` 是否连通 | 是，连通为 `1`，否则为 `0` |

连边时，如果 `u == v`，或两点已经连通，就忽略本次操作；否则添加边。这样图始终是森林，即每个连通分量都是一棵树，不会产生环。

断边时，只有两点之间**直接存在一条边**才删除它。两点连通不代表它们之间有直接边；不存在的边和自环断边都忽略。边没有方向，`cut(u, v)` 与 `cut(v, u)` 的含义相同。

在 `Solution` 类中实现：

```cpp
std::vector<int>
dynamicConnectivity(int n,
                    const std::vector<std::array<int, 3>> &operations);
```

返回数组只保存连通性查询的结果，顺序与查询出现的顺序一致。不需要编写 `main` 或处理输入输出。

- `1 ≤ n ≤ 100000`，`0 ≤ operations.size() ≤ 200000`。
- 所有操作类型与节点编号均合法，但可能出现上述应当忽略的连边、断边请求。
- 一个节点始终与自身连通，所以 `{2, u, u}` 返回 `1`。
- 没有查询时返回空数组；同一个 `Solution` 对象的多次调用都从新的孤立点森林开始。
- 目标：使用 LCT，每次操作均摊 `O(log n)`，辅助空间 `O(n)`；另需保存返回数组。

## 手算：路径存在，不等于直接边存在

```text
n = 3
operations = [[0, 0, 1], [0, 1, 2], [2, 0, 2],
              [1, 0, 2], [2, 0, 2], [1, 1, 2], [2, 0, 2]]
answer     = [1, 1, 0]
```

前两次操作建立链 `0—1—2`。节点 `0` 和 `2` 之间存在路径，所以第一次查询返回 `1`。

接着尝试删除 `0—2`。森林中只有边 `0—1` 和 `1—2`，并没有直接边 `0—2`，因此这次操作必须忽略，第二次查询仍返回 `1`。

删除 `1—2` 后，森林分成 `0—1` 和孤立点 `2`，最后一次查询返回 `0`。如果把一次 `cut` 错写成断开整条路径，就会在第四个操作中提前破坏连通性。

## 第一步：区分实际森林与辅助二叉树

LCT 同时涉及两种结构。

**实际森林**就是题目中的节点和无向边。为了描述祖先路径，LCT 会为每棵树选择一个当前根；这个根可以改变，但换根本身不改变无向边。

**辅助 Splay**只是一种表示方法。LCT 在有根树中选择若干父子边作为首选边，使每个节点至多有一个首选孩子。连续首选边形成路径，每条路径用一棵 Splay 表示，其中序顺序按实际树上从浅到深的方向排列。

辅助树的一条父子边不一定是实际森林中的直接边。它表示路径顺序中的二叉树关系；旋转只改变辅助表示，不会给实际森林添加或删除边。

这与第 14 题的重链也不同：首选路径会随着访问调整，不要求选择子树最大的孩子，也不预先固定链头。

## 第二步：父指针为什么有两种含义？

下面采用常见的单一父指针实现。用内部编号 `0` 表示空节点，将用户节点 `v` 映射为内部节点 `v + 1`。每个节点至少保存左右孩子、父指针 `fa` 和翻转标记 `rev`。

`fa[x]` 的含义取决于 `x` 是否为辅助树根：

- 如果 `x` 是某个辅助节点的左孩子或右孩子，`fa[x]` 就是普通 Splay 父节点。
- 如果 `x` 是辅助树根，`fa[x]` 可以指向这条路径最上端节点在实际树中的父节点，称为路径父亲。它连接到另一条首选路径，也可能为空。

因此，辅助树根不一定满足 `fa[x] == 0`。正确判断是：

```text
isAuxRoot(x) =
    fa[x] == 0
    或者 fa[x] 的左孩子和右孩子都不是 x
```

注意路径父亲属于整条辅助路径，并不一定是辅助根节点 `x` 自己在实际树中的父节点；旋转后，辅助根可以是路径中的其他节点。

### 与第 16 题的 Splay 有哪些实现差别？

`splay(x)` 只把 `x` 旋到当前辅助树的根，停止条件使用 `isAuxRoot(x)`。收集待下传标记的祖先时，也只收集当前辅助树内的祖先，不能沿路径父亲继续进入另一棵辅助树。

旋转 `x` 时，如果旧父节点 `p` 不是辅助根，就按普通 Splay 的方式更新祖父的孩子指针；如果 `p` 已经是辅助根，就让 `x` 继承它的路径父亲，不去修改那个路径父亲的左右孩子。

翻转标记的处理仍沿用第 16 题：旋转前按祖先到后代下传，应用翻转时交换左右孩子并异或 `rev`。

## 第三步：access 怎样把根到 x 的路径暴露出来？

本讲义统一采用以下约定：**`access(x)` 结束时会执行一次 `splay(x)`**。因此调用完成后，`x` 是辅助根，整个辅助树表示当前实际根到 `x` 的路径，`x` 没有右孩子。

它可以按下面的步骤实现。`last` 表示已经接好的下半段路径，初始为空：

```text
last = 0
从 y = x 开始，重复直到 y 为空：
    splay(y)
    保存 next = fa[y]            // 此时它是上一条路径的入口
    把 y 的右孩子改为 last
    若 last 非空，令 fa[last] = y
    重新计算 y 的辅助树统计（如果有）
    last = y
    y = next
最后 splay(x)
```

`splay(y)` 之后，`y` 的左子树表示当前首选路径上比 `y` 浅的部分，右子树表示比 `y` 深的部分。我们要建立通向目标 `x` 的路径，因此保留左侧，把右侧替换为已经接好的 `last`。

### 被替换掉的旧右孩子怎么办？

旧右子树离开当前辅助树，成为另一条首选路径。**不要把旧右孩子的父指针清零**：它仍应指向 `y`，只是这个指针从辅助父关系转为路径父关系，因为 `y` 已不再把它列为孩子。

这正是根判断必须检查孩子指针的原因。若清零这个父指针，就会丢失实际树中两条路径之间的连接；若始终把非零父指针当作辅助父关系，又会跨越辅助树边界旋转。

`access` 只改变哪些边被选为首选边，实际森林的边集合保持不变。

## 第四步：换根与寻找实际根

### makeroot(x)：让 x 成为当前实际根

先执行 `access(x)`，此时辅助树按旧根到 `x` 的顺序表示整条路径。再对 `x` 应用翻转标记，就把这条路径的方向反过来，让 `x` 成为新的实际根：

```text
makeroot(x):
    access(x)
    applyReverse(x)
```

这里翻转的是路径顺序，不是删除或反向存储某条无向边。路径之外的分支仍通过路径父关系连接在各自节点上。

### findroot(x)：寻找 x 所在实际树的根

先执行 `access(x)`。根到 `x` 的路径已经在同一棵辅助树中，其中序最左侧的节点就是实际根。

从 `x` 开始，每次先 `push` 当前节点，再沿左孩子走，直到没有左孩子。最后把找到的节点 Splay 到辅助根，并返回它。最后的 Splay 是访问调整的一部分，不应省略成在可能很深的辅助树上反复只查找。

`findroot` 本身不改变实际根，所以比较 `findroot(u)` 与 `findroot(v)` 是否相同，就能判断两点是否连通。

## 第五步：组合成 link 和 cut

### link(u, v)：连接两棵不同的树

如果 `u == v`，直接忽略。否则先执行 `makeroot(u)`，再检查 `findroot(v)`：

- 如果返回 `u`，说明两点已经在同一棵树中，添加边会成环，忽略。
- 否则两点属于不同的树，令 `fa[u] = v`，以路径父关系接上一条新边。

此时 `u` 是它所在实际树的根，也是辅助根。这里不能随意将 `u` 设为 `v` 的左孩子或右孩子；连边建立的是实际树连接，不需要立即把两点放进同一条首选路径。

### cut(u, v)：只删除直接边

自环直接忽略；两点不连通时也忽略。若连通，执行：

```text
makeroot(u)
access(v)
```

现在 `v` 是辅助根，整棵辅助树按从 `u` 到 `v` 的顺序表示这条路径，所有内部节点都在其中。

要确认两点之间只有一条直接边，检查：

```text
left[v] == u 且 right[u] == 0
```

读取方向前应确保相关翻转标记已按需下传。如果满足条件，就令 `left[v] = 0`、`fa[u] = 0`，再重新计算 `v` 的统计；否则忽略。

为什么还要检查 `right[u]`？因为即使 `u` 是 `v` 的左孩子，中间仍可能通过 `u` 的右子树存放其他路径节点。`u` 是整条路径的最左端，故在暴露后的逻辑顺序中没有左侧节点；只有右侧也没有中间节点，才能说明路径恰好包含 `u, v` 两点。

主例中尝试删除 `0—2` 时，暴露路径会得到 `0, 1, 2` 三个节点，中间的节点 `1` 会让直接边条件失败，森林因此保持不变。

## 正确性与均摊复杂度

辅助旋转和 `access` 保持实际森林的边不变；`makeroot` 只改变描述祖先关系的方向。于是 `findroot` 可以在当前表示下找到每个连通分量唯一的实际根，用根是否相同判断连通性。

`link` 只连接不同分量，因此不会形成环。`cut` 只在暴露路径恰好是一条直接边时断开连接，因此不会误删路径中的其他边。这些性质使每次操作后维护的森林与题意一致。

标准 LCT 的访问与 Splay 调整具有均摊 `O(log n)` 的复杂度保证。不能把 `access` 中每轮 Splay 分别估成 `O(log n)` 后再假设轮数固定；这个界限来自对整串路径调整的联合均摊分析。单次操作可能较慢，目标是操作序列的总成本为 `O((n + m) log n)` 量级。

每个节点只保存常数个字段，辅助空间为 `O(n)`。所有 Splay 祖先收集和下传都可使用显式栈，无需深递归。

## 检查与运行

编辑 [exercises/17.cppm](../exercises/17.cppm) 时，先完成辅助根判断与 Splay，再完成 `access`、`makeroot`、`findroot`，最后组合公开操作。重点检查：

1. 初始孤立点与自身连通，不同孤立点不连通。
2. 重复连同一条边、反向重复连边、自环，以及试图连接已连通的非相邻节点。
3. 删除不存在的边，特别是两点连通但不相邻的情况。
4. 正向或反向删除直接边、重复删除、删除后重新连接。
5. 在不同端点上交替查询和换根，确认首选路径变化不丢失实际边。
6. 长链、星形森林、空操作列表与同一对象的多次调用。

小规模时，可以用邻接表保存实际边，并用 BFS 检查连通性，与每次 LCT 查询对照。朴素模型删除时也必须检查直接边，才能正确验证无效断边。
