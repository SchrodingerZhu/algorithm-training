# 18 · LCT 综合：动态路径点权和

第 17 题已经能在动态森林中连边、断边，并判断两点是否连通。这一题再给每个节点加上权值，允许修改点权，并查询当前森林中两点之间的路径和。

关键是第 17 题的路径暴露操作：先让一个端点成为实际根，再访问另一个端点，就能让一棵辅助 Splay 恰好表示这条路径。只要维护辅助子树的点权和，就能读出答案。

## 题目与函数接口

给定非空数组 `values`，节点 `v` 的初始点权为 `values[v]`。初始时所有节点都孤立，没有边。

按输入顺序处理：

| 操作 | 含义 | 是否产生答案 |
|---|---|---|
| `{0, u, v}` | 尝试添加无向边 `u—v` | 否 |
| `{1, u, v}` | 尝试删除无向边 `u—v` | 否 |
| `{2, u, value}` | 将节点 `u` 的点权赋为 `value` | 否 |
| `{3, u, v}` | 查询当前 `u` 到 `v` 路径上的点权和 | 是 |

连边、断边遵守第 17 题的规则：自环和会成环的连边忽略，不存在的直接边也不能删除。点赋值覆盖旧值，不是增加一个增量；节点即使孤立，也可以赋值。

查询时，如果两点连通，返回包含两个端点的路径和；如果不连通，返回 `std::nullopt`，表示不存在这条路径。`u == v` 时一定连通，路径只有该节点，答案是它的当前点权。

在 `Solution` 类中实现：

```cpp
std::vector<std::optional<long long>>
dynamicPathSum(const std::vector<long long> &values,
               const std::vector<std::array<long long, 3>> &operations);
```

返回数组只为类型 `3` 的查询保存结果，顺序与查询出现的顺序一致。不要为连边、断边或赋值输出占位项。不需要编写 `main` 或处理输入输出。

- `1 ≤ n = values.size() ≤ 100000`，`0 ≤ operations.size() ≤ 200000`。
- 初始点权和赋值的 `value` 都在 `[-10⁹, 10⁹]` 内。
- 所有节点编号从 `0` 开始且合法，所有操作类型合法。
- 三元组的第三项在类型 `2` 中是权值，在其他类型中是节点编号，应按操作类型解释。
- 没有查询时返回空数组；同一个 `Solution` 对象的多次调用应重新建立初始孤立点森林。
- 目标：使用 LCT，每次操作均摊 `O(log n)`，辅助空间 `O(n)`；另需保存返回数组。

## 手算：连接、赋值和断开分别改变什么？

```text
values = [2, -1, 4]
operations = [[3, 0, 2], [0, 0, 1], [0, 1, 2], [3, 0, 2],
              [2, 1, 5], [3, 2, 0], [1, 1, 2], [3, 0, 2]]
answer = [nullopt, 5, 11, nullopt]
```

| 操作 | 当前状态或计算 | 输出 |
|---|---|---|
| 查询 `0` 到 `2` | 初始两点孤立，没有路径 | `nullopt` |
| 连接 `0—1` | 建立一条边，点权保持不变 | 不输出 |
| 连接 `1—2` | 形成链 `0—1—2` | 不输出 |
| 查询 `0` 到 `2` | 路径和为 `2 + (-1) + 4` | `5` |
| 将节点 `1` 赋为 `5` | 点权变为 `[2, 5, 4]`，边保持不变 | 不输出 |
| 查询 `2` 到 `0` | 反向经过同一路径，和为 `4 + 5 + 2` | `11` |
| 删除 `1—2` | 分成 `0—1` 与孤立点 `2` | 不输出 |
| 查询 `0` 到 `2` | 两点已经断开 | `nullopt` |

这里 `nullopt` 不是数值 `0` 或 `-1`。例如两个相连节点的权值分别为 `2` 和 `-3`，路径和就是合法的 `-1`，必须返回一个有值的 `optional`。

## 第一步：在辅助 Splay 中增加点权与总和

保留第 17 题的左右孩子、父指针和翻转标记，再增加：

| 字段 | 含义 |
|---|---|
| `val[x]` | 节点 `x` 当前的点权 |
| `sum[x]` | 节点 `x` 的辅助 Splay 子树中，所有节点的点权和 |

采用内部 `0` 号节点为空的约定时，令 `sum[0] = 0`，用户节点 `v` 仍映射为内部节点 `v + 1`。所有真实节点初始没有孩子或父亲，`sum[x] = val[x]`。

重新聚合公式为：

```text
sum[x] = sum[left[x]] + val[x] + sum[right[x]]
```

这里的 `sum[x]` **不是实际森林中以 x 为根的整棵子树之和**，也不是连通分量的总和。它只统计当前辅助二叉树中的节点，而这些节点属于某条首选路径的一段。

### 为什么不加路径父亲或其他分支的权值？

路径父关系连接不同的辅助树。那些通过非首选边连接的分支，有时称为虚子树；它们不属于当前辅助路径，因此不进入上面的 `pull` 公式。

例如实际树有边 `0—1`、`1—2`、`1—3`，要查询 `0` 到 `2` 时，节点 `3` 不在路径上。即使它仍连接在节点 `1` 上，也不能把它的权值加进路径和。本题只维护路径统计，不需要维护虚子树的总和。

## 第二步：每次辅助结构变化都保持 sum 正确

第 17 题只问连通性，节点没有权值统计。加入 `sum` 后，需要在以下位置重新聚合：

1. **旋转之后**，先 `pull` 下降的旧父节点，再 `pull` 上升的新父节点。
2. **`access` 更换右孩子之后**，对当前节点执行 `pull`，因为它所包含的辅助路径片段已经改变。
3. **成功断边之后**，清除暴露路径的连接，并对保留为辅助根的节点执行 `pull`。
4. **点赋值之后**，对被赋值且已经调整到辅助根的节点执行 `pull`。

`link` 通过路径父指针连接不同辅助树时，不需要立即把整棵被连接树的和加入另一棵辅助树；下一次 `access` 会按需要重建路径，并在换孩子时重新聚合。

### 翻转标记会怎样影响 sum？

换根时仍会交换左右孩子并异或翻转标记。翻转只改变路径顺序，不改变这段路径上的节点集合，因此总和保持不变，不需要改变 `sum`。

这依赖加法与方向无关。以后若维护字符串拼接等与顺序有关的信息，就不能直接照搬只存一个总和的做法；本题只需维护一个 `sum`。

## 第三步：怎样查询 u 到 v 的路径和？

沿用第 17 题的约定：`access(x)` 最后执行 `splay(x)`。一次查询分为两步。

### 先判断是否连通

比较 `findroot(u)` 与 `findroot(v)`。不同则返回 `std::nullopt`，本次查询结束。

不能先把某个辅助树的和当作答案，再根据数值猜测是否连通。辅助树总和始终是一个合法数值，即使两点之间根本没有路径。

### 再把目标路径变成一棵辅助树

两点连通时，依次执行：

```text
makeroot(u)
access(v)
答案 = sum[v]
```

`makeroot(u)` 让 `u` 成为当前实际根。之后 `access(v)` 暴露实际根到 `v` 的路径，也就是 `u` 到 `v` 的目标路径，并把 `v` 调整为辅助根。

此时这棵辅助树包含路径上的全部节点，且不包含旁支。由于 `sum[v]` 统计整棵辅助树，其值恰好等于路径点权和，两个端点也自然包含在内。

这里不需要哨兵，也不需要像第 16 题那样再取某个孩子的子树。第 16 题把数组区间夹在两个边界之间；LCT 的换根与访问已经让整棵辅助树直接表示目标路径。

## 第四步：点赋值为什么要先 access？

修改节点 `u` 时，执行：

```text
access(u)
val[u] = value
pull(u)
```

如果直接改 `val[u]` 而不调整辅助树，当前辅助祖先的 `sum` 可能仍包含旧点权。只对 `u` 执行 `pull` 也不能修复它上方所有辅助祖先。

先 `access(u)` 后，`u` 是辅助根，没有需要向上修复的辅助祖先。它的孩子统计已经由访问过程维护好，所以改值后一次 `pull(u)` 就能恢复这一棵辅助树的正确总和。

其他辅助树通过路径父关系连接到这里，但它们的 `sum` 本来就不包含这些外部分支，因此不需要同步更新。以后某条查询路径包含 `u` 时，`access` 会把相关路径接起来，并使用新的 `val[u]` 重新计算。

赋值使用新的 `value` 覆盖旧权值，不能写成 `val[u] += value`。断边也不会重置节点的权值；重新连接后应继续使用它最后一次赋值的结果。

## 跟踪一次带旁支的查询

考虑下面的实际树，节点 `3` 是主路径旁边的一条分支：

```text
点权：values = [2, -1, 4, 100]
边：  0—1，1—2，1—3

0:2 — 1:-1 — 2:4
        |
      3:100
```

查询 `0` 到 `2` 时，`makeroot(0)`、`access(2)` 暴露节点序列 `0, 1, 2`。节点 `3` 通过其他辅助路径连接着，但不属于这棵表示目标路径的 Splay，因此结果是 `5`，不是 `105`。

将节点 `1` 赋为 `5` 后：

- 查询 `0` 到 `2`，结果为 `2 + 5 + 4 = 11`。
- 查询 `3` 到 `2`，会重新暴露另一条路径 `3, 1, 2`，结果为 `100 + 5 + 4 = 109`。
- 查询 `1` 到自身，结果为 `5`，不包含任何相邻节点。

不同查询会改变首选路径和辅助树形，但它们读取的始终是实际森林中的唯一路径。

## 正确性、数值范围与复杂度

连边和断边沿用第 17 题的检查，所以维护的边集合始终符合题意。每次旋转、换孩子和赋值后进行 `pull`，保证每个辅助子树的 `sum` 正确。路径暴露又让辅助根的子树恰好等于目标路径，三者合起来保证查询答案正确。

每条路径最多包含 100000 个节点，每个当前点权的绝对值最多为 `10⁹`，因此路径和的绝对值最多为 `10¹⁴`。`val`、`sum` 和返回值都应使用 `long long`。

每个公开操作只组合常数次 LCT 基本操作，增加总和统计只给每次旋转或重接增加常数工作。因此每次操作仍为均摊 `O(log n)`，辅助空间为 `O(n)`，另需 `O(q)` 保存 `q` 次查询的结果。单次操作的耗时可能高于这个均摊界限。

## 检查与运行

编辑 [exercises/18.cppm](../exercises/18.cppm) 时，先给第 17 题的辅助操作补上 `pull`，再实现路径查询和点赋值。重点检查：

1. 孤立点到自身返回当前点权，不同孤立点之间返回 `nullopt`。
2. 合法路径和为 `0`、`-1` 或其他负数时，都应返回有值的 `optional`。
3. 路径中间节点赋值后，正向和反向查询得到相同的新路径和。
4. 旁支上有很大的点权，确保它不会进入不经过该分支的路径和。
5. 无效连边和无效断边不改变结果；有效断边后返回 `nullopt`，重新连接后恢复查询。
6. 断开的节点仍可赋值，重新连接后保留新点权。
7. 大点权长链、空操作列表、只有修改的列表和同一对象的多次调用。

小规模对照可以用邻接表维护实际森林，用 BFS 找到查询路径，再逐点求和。每次随机连边、断边或赋值后比较查询结果，尤其检查频繁换根和切换分支的情况。
