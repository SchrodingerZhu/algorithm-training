# 06 · 离线 RMQ：单调栈与并查集

## 题目

给定一个长度为 `n` 的整数数组 `values`，以及 `q` 个区间查询 `queries`。数组在整个过程中保持不变，没有修改操作。

每个查询 `queries[i] = {l, r}` 要求你求出闭区间 `[l, r]` 中的最小值，也就是：

```text
min(values[l], values[l + 1], ..., values[r])
```

这种查询称为区间最小值查询，英文为 Range Minimum Query，简称 **RMQ**。

返回一个长度为 `q` 的数组 `answer`，其中 `answer[i]` 对应输入中的第 `i` 个查询。返回的是最小值的数值；即使多个位置具有相同的最小值，也只输出这个数值。

本题练习利用“所有查询提前已知”这一条件，使用**单调栈与并查集**，按查询的右端点离线处理。下面先给出完整的接口和规则，算法提示可以按需展开。

## 函数接口

在 `Solution` 类中实现：

```cpp
std::vector<long long>
rangeMin(const std::vector<long long> &values,
         const std::vector<std::array<int, 2>> &queries);
```

| 参数或返回值 | 含义 |
|---|---|
| `values` | 待查询的整数数组，下标从 `0` 开始 |
| `queries[i][0]` | 第 `i` 个查询的左端点 `l`，包含在区间内 |
| `queries[i][1]` | 第 `i` 个查询的右端点 `r`，包含在区间内 |
| 返回值 `answer[i]` | `values[l..r]` 中的最小值，类型为 `long long` |

只需要完成这个成员函数及其辅助代码，不需要编写 `main`、读取标准输入或打印答案。评测程序会直接调用函数。

## 数据范围与约定

- `1 ≤ n = values.size() ≤ 200000`。
- `0 ≤ q = queries.size() ≤ 200000`。
- `-10^9 ≤ values[i] ≤ 10^9`，允许负数和重复值。
- 每个查询都满足 `0 ≤ l ≤ r < n`；输入保证合法，无须处理越界查询。
- 区间是**闭区间**，包含两个端点，共有 `r - l + 1` 个元素。`l == r` 时答案就是 `values[l]`。
- 查询的输入顺序任意，左右端点都不保证递增；查询可以重复，区间可以重叠。
- `queries` 为空时返回空数组。`values` 保证非空。
- 同一个 `Solution` 对象可能被多次调用，每次调用应独立计算，不能使用上次调用遗留的数据。

## 示例

### 示例 1：查询顺序与单点区间

```text
values  = [5, 3, 4, 1]
queries = [[0, 2], [1, 3], [2, 2]]
answer  = [3, 1, 4]
```

| 查询编号 | 闭区间 | 区间中的元素 | 最小值 |
|---|---|---|---|
| `0` | `[0, 2]` | `[5, 3, 4]` | `3` |
| `1` | `[1, 3]` | `[3, 4, 1]` | `1` |
| `2` | `[2, 2]` | `[4]` | `4` |

如果按右端点处理，可以先计算编号 `0` 和 `2` 的查询，再计算编号 `1`。但返回数组仍然必须按原编号排列，所以结果是 `[3, 1, 4]`。

### 示例 2：负数、重复最小值与重复查询

```text
values  = [4, -2, -2, 7]
queries = [[2, 3], [0, 0], [0, 3], [1, 2], [2, 3]]
answer  = [-2, 4, -2, -2, -2]
```

`[1, 2]` 中两个元素都是 `-2`，答案仍然只有一个数值 `-2`。第一个和最后一个查询相同，它们各自在返回数组中占一个位置。

### 示例 3：没有查询

```text
values  = [8]
queries = []
answer  = []
```

## “离线处理”是什么意思

函数被调用时，整个 `queries` 数组已经给出。你可以先查看所有查询，再安排它们的计算顺序；只要最终恢复输入顺序即可。这就是本题中“离线”的含义。

本题要求按右端点 `r` 从小到大处理查询。这样，右端点相同的查询可以共享同一份计算状态。你需要考虑如何维护这份状态，以及如何保留每个查询的原编号。

## 算法要求与复杂度

- 使用单调栈与并查集完成离线 RMQ。这两个结构分别帮助你维护候选位置，以及快速跳过已经被淘汰的位置。
- 本题不使用稀疏表（Sparse Table，简称 ST）或转化为树上的最近公共祖先（Lowest Common Ancestor，简称 LCA）查询。
- 目标总时间复杂度为 `O((n + q) α(n))`，总空间复杂度为 `O(n + q)`，包括组织查询和保存答案所需的空间。

`α(n)` 是反阿克曼函数，增长极慢，可以先把这个时间目标理解为“接近线性”。这是对一整批操作的**摊还**复杂度要求，不要求每一次查询都只执行常数步。你不需要实现或计算 `α(n)`。

复杂度与并查集的具体实现有关：可以先写出正确的路径压缩版本，再按提示 4 检查达到上述时间目标还需要什么。不要把“使用了并查集”直接等同于具有 `α(n)` 的复杂度。

## 分步提示

可以先独立思考。下面的提示从组织查询逐步深入到维护规则，均可单独展开。

<details>
<summary>提示 1：怎样组织查询，避免反复扫描数组？</summary>

右端点只可能是 `0` 到 `n - 1`。可以为每个右端点准备一个查询列表，把所有右端点为 `r` 的查询放在一起，每项保留左端点和原查询编号。

随后从左到右扫描 `values`。将位置 `r` 纳入维护状态后，处理右端点恰好为 `r` 的全部查询，把结果写回各自的原编号。

这种按右端点分组的方式称为“分桶”，组织查询需要 `O(n + q)` 时间和空间。若改用比较排序，要把额外的 `O(q log q)` 时间计入分析。

</details>

<details>
<summary>提示 2：新元素到来时，哪些旧位置可以被淘汰？</summary>

假设 `j < r` 且 `values[j] > values[r]`。对于右端点至少为 `r`、并且包含 `j` 的查询，位置 `r` 也一定在区间内，而且它的值更小。因此在这些查询中，不必再把 `j` 当作最小值候选。

用一个栈保存候选的**下标**。下标从栈底到栈顶递增，对应的数值保持非递减。扫描到 `r` 时，反复弹出值大于 `values[r]` 的栈顶，最后把 `r` 入栈。这就是这里所用的单调栈。

相等的值可以保留；采用“严格大于才弹出”的规则，就能保持上述非递减关系。每个下标最多入栈、出栈各一次。

</details>

<details>
<summary>提示 3：被弹出的下标还出现在查询里，怎么办？</summary>

查询左端点可能恰好是一个已经弹出的下标，所以需要记住它后来被谁替代。

一种直接的表示是：初始时每个位置的 `parent` 指向自己；当位置 `j` 被新位置 `r` 淘汰时，让 `parent[j]` 指向 `r`。沿父指针不断前进，直到到达指向自己的位置，记这个查找操作为 `find`。

扫描完位置 `r` 后，`find(l)` 应当指向区间 `[l, r]` 中的一个最小值位置。注意，此时只处理了数组前缀 `[0, r]`；如果先扫描完整个数组再回答全部查询，查找就可能越过某个查询的右边界。

可以在查找后把沿途位置直接连向找到的代表，这叫**路径压缩**，能减少以后的重复跳转。递减数组可能形成很长的父链，查找实现应能处理长链，避免依赖过深的递归。

在这个表示中，代表位置具有“最小值候选”的含义。不能直接套用普通并查集的按大小合并、随意交换根，否则会破坏这个含义。

</details>

<details>
<summary>提示 4：实现后再看——怎样分析并查集部分的复杂度？</summary>

单调栈总共进行 `O(n)` 次入栈、出栈，分桶和写回答案共需 `O(n + q)` 时间。剩下要分析的是父指针查找。

提示 3 的直接表示固定了父指针方向。仅使用路径压缩时，可以使用总时间 `O((n + q) log n)` 的上界；不要直接套用“路径压缩加按秩合并”的反阿克曼界。

若要达到题目给出的 `O((n + q) α(n))` 目标，可以将“并查集的根”与“当前最小值的位置”分开保存。这样，并查集就能同时使用路径压缩和按大小或按秩合并；每次合并后，另外记录该集合对应的最小值位置。按大小合并指把元素较少的集合的根连接到较大集合的根。

这里的关键检查是：查找返回的根编号是否仍然等于答案位置？如果允许按大小选择根，就必须从该根保存的信息中取得答案位置。这种分离代表信息的做法也见于 [CP-Algorithms 的离线 RMQ 说明](https://cp-algorithms.com/data_structures/disjoint_set_union.html#offline-rmq-range-minimum-query-in-oalphan-on-average-arpas-trick)。

</details>

实现后，先检查上面的示例，再检查以下情况：

- 单元素数组的 `[0, 0]` 查询，以及空查询列表。
- 全部元素相等、包含负数、严格递增或严格递减的数组。
- 多个查询有相同右端点，查询输入顺序被打乱，以及重复查询。
- 覆盖整个数组的查询和紧邻边界的单点查询。
- 对同一个 `Solution` 对象，先后传入不同数组。
