# 22 · 独立练习：部门收支与拆分查询

一家公司有 n 名员工，编号为 `0..n-1`。员工之间有若干条无向的直接协作关系，且这些关系始终形成森林。每个连通分量视为一个部门。初始没有协作关系，每名员工各属一个单人部门。

每名员工负责一项业务，其净收支为 values[u]：正数表示盈余，负数表示亏损。公司会新增或撤销协作关系、更新业务收支，并查询某个部门的净收支。还需要回答假设拆分的问题：若撤销直接关系 u—v，包含 v 的那一侧合计收支是多少？假设查询不实际撤销关系。

## 题目与接口

```cpp
std::vector<std::optional<long long>> companyBudget(
    const std::vector<long long>& values,
    const std::vector<std::array<long long, 3>>& operations);
```

values 给出各员工的初始净收支。

| 操作 | 含义 |
|---|---|
| `{0,u,v}` | 新增直接关系 u—v；自环或两点已经连通则忽略 |
| `{1,u,v}` | 撤销直接关系 u—v；不存在则忽略，参数顺序无关 |
| `{2,u,w}` | 将员工 u 的净收支赋为 w |
| `{3,u,0}` | 查询 u 所在整个部门的净收支和 |
| `{4,u,v}` | 假设移除直接边 u—v，查询含 v 的那侧净收支；直接边不存在则返回 nullopt |

只返回类型 3、4 的答案。类型 3 总有值；类型 4 中 `u==v` 也返回 nullopt。边本身无方向，但类型 4 的参数有方向：交换 u、v 会查询另一侧。`1 ≤ n = values.size() ≤ 100000`，操作数不超过 200000，净收支在 `[-10⁹,10⁹]`。编号和类型合法，保留字段为 0。没有查询返回空数组；同一对象多次调用独立。目标为每次期望 `O(log n)`，辅助空间 `O(n)`，另计返回数组。

```text
values = [10,20,-5,100]
operations = [[0,0,1], [0,1,2], [0,1,3], [3,0,0],
              [4,0,1], [4,1,0], [4,1,3],
              [2,3,-10], [4,0,1], [3,2,0], [4,0,2]]
answer = [125,115,10,100,5,15,nullopt]
```

撤销 0—1 的假设中，1 一侧包含 `{1,2,3}`，初始和为 115；反向查询 0 一侧只有 10。修改员工 3 后，1 一侧和变为 `20-5-10=5`，全部门为 15。0—2 虽然有路径，但没有直接边。

返回数组按查询出现的顺序排列，不需要 main 或输入输出。可以先独立思考，再展开实现提示。

<details><summary>实现提示：给可换根 ETT 增加边侧区间查询</summary>

可以使用第 19 题的环形游走，加上第 20 题的分量和。V(u) 表示员工 u 的唯一顶点记录，E(u,v) 表示沿一条直接边从 u 到 v 的记录；每条无向边保存两个方向。

## 第一步：每个员工只贡献一次

V(u) 的 value 为员工净收支，E(u,v) 的 value 恒为 0。增加普通 Treap 的 sum 聚合：

```text
sum[x] = sum[left[x]] + value[x] + sum[right[x]]
```

初始化孤立点、merge/split 改孩子、回收并重新使用边卡片时，都应保持这条式子。与第 18 题不同，这棵辅助树包含整个分量的游走，所以 `sum[root(vertex[u])]` 就是整个部门的净收支，不需要暴露某条路径。

为什么不能每经过一次 u 就加一次净收支？高连接度员工会被多次经过。唯一的 V 卡解决重复计数，即使净收支为 0 也不能把 V 卡当作边卡片。

## 第二步：点赋值

用固定句柄找到 V(u)，覆盖自己的 value，自底向上沿 Treap 父链 pull 到根。净收支会跟着卡片移动，不随 reroot、连边或断边重置。赋值不是加法；断开的员工仍可赋值。

收支和使用 long long，最多 100000 人、每人绝对值不超过 10⁹，和的绝对值不超过 10¹⁴。合法的 0 或 -1 与不存在直接边的 nullopt 必须区分。

## 第三步：边的一侧就是两次过桥之间

查边表得到 a=E(u,v)、b=E(v,u)。将序列旋到 a 开头后，第 19 题已经证明序列是：

```text
a + P + b + Q
```

P 恰好遍历 v 侧，Q 恰好遍历 u 侧。因此分离 P 后读它的 sum 就能回答类型 4。先旋到 a，再令 j=rank(b)，按 `split(T,1)`、`split(剩余,j-1)`、`split(剩余,1)` 分离 a、P、b、Q。必须先查直接边；仅有路径时不能使用这个公式。

这次是查询，不删除边卡片、不修改边表、不回收节点。读完之后拼回 `a+P+b+Q`。返回的环仍表示原来的部门；切口可以改变，因为题目没有对外查询切口。

也可以先执行真实 cut，记录 v 分量和，再 link 回去，但入门时建议直接分离再恢复，便于检查句柄和边表始终对应同一对卡片。

## 这与「换根后的子树和」有什么关系？

如果给实际树选根 r，并且已知 u 是 v 在该根下的直接父亲，那么移除 u—v 后的 v 侧就是 v 的有根子树。本题直接给出边的两个端点与查询方向，避免同时引入动态寻找父亲的问题。

不要直接把 `V(v)` 到序列末尾视为 v 子树；V 卡与第 21 题的进入括号含义不同。也不要把 ETT 的循环移位当作已经维护了每个人的实际父亲。任意给定根 r 和节点 v 的子树查询还需定位 r 到 v 方向上的相邻边，本题不要求这一额外操作。

## 分段练习与提示

先只测试类型 3 与赋值，再加入类型 4，最后交替边查询、真实断边和重新连边。

<details><summary>如何用朴素森林对拍？</summary>

小数据用邻接表保存实际边。整个部门查询从 u 做 BFS 累加。边侧查询先检查直接边是否存在，再从 v 做 BFS，但禁止经过 u—v 这条边，累加可到达节点。无需真实删除与恢复邻接表，避免对照模型也忘记恢复边。对每条存在的边，两个方向的答案相加应等于分量总和；查询前后分量总和应保持不变。

</details>

每次只增加常数次切拼或一条父链上的 pull，复杂度仍为期望 `O(log n)`。空间沿用第 19 题的边卡片回收策略。

</details>
