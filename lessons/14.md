# 14 · 树链剖分：路径最小点权

第 13 题把整棵子树变成了一个数组区间。现在查询对象改为任意两点之间的路径：路径可能向上经过公共祖先，再沿另一条分支向下，通常不会在普通 DFS 序中形成一个区间。

树链剖分（Heavy-Light Decomposition，HLD）会把路径拆成少量连续区间。每段仍交给线段树处理，最后把各段的最小值合并起来。

## 题目与函数接口

`parent` 描述一棵根为 `0` 的非空树，`parent[0] = -1`；`values[v]` 是节点 `v` 的初始点权。树的边始终不变。

按输入顺序处理以下操作：

| 操作 | 含义 | 是否产生答案 |
|---|---|---|
| `{0, v, value}` | 将节点 `v` 的点权赋为 `value` | 否 |
| `{1, u, v}` | 查询从 `u` 到 `v` 的唯一路径上的最小点权 | 是 |

路径包含两个端点和路径中间的所有节点。特别地，`u == v` 时路径只有这个节点，答案是它的当前点权，不是 `0`。

在 `Solution` 类中实现：

```cpp
std::vector<long long>
pathMinUpdates(const std::vector<int> &parent,
               const std::vector<long long> &values,
               const std::vector<std::array<long long, 3>> &operations);
```

返回数组只保存查询答案，顺序与查询出现的顺序相同。不需要编写 `main` 或处理输入输出。

- `1 ≤ n = parent.size() = values.size() ≤ 200000`。
- `0 ≤ operations.size() ≤ 200000`，节点编号从 `0` 开始且均合法。
- 初始点权和赋值的 `value` 都在 `[-10⁹, 10⁹]` 内。
- 输入树合法，父编号不保证小于子编号。
- 没有查询时返回空数组；同一个 `Solution` 对象的多次调用应独立计算。
- 目标：`O(n)` 预处理，点赋值 `O(log n)`，路径查询 `O(log² n)`，辅助空间 `O(n)`。

## 手算一条跨过根的路径

```text
parent = [-1, 0, 0, 1]
values = [ 5, 4, 3, 2]

        0:5
       /   \
     1:4   2:3
     /
   3:2

operations = [[1, 3, 2], [0, 1, -7], [1, 3, 2], [1, 2, 2]]
answer     = [2, -7, 3]
```

第一次查询走过 `3 → 1 → 0 → 2`，点权依次是 `2, 4, 5, 3`，最小值为 `2`。把节点 `1` 赋为 `-7` 后，同一路径的最小值变成 `-7`。最后查询节点 `2` 到自身，只返回它的点权 `3`。

这里维护的是点权。第 11 题的边权路径可以排除公共祖先的入边；本题必须保留公共祖先这个节点本身。

## 第一步：用子树大小区分重边和轻边

先以 `0` 为根，计算每个节点的深度 `depth[v]` 和子树节点数 `size[v]`，其中子树大小包含节点自身。

对每个有孩子的节点 `v`，选择子树最大的一个孩子作为重儿子，记为 `heavy[v]`。如果多个孩子一样大，任意选择一个即可。叶子没有重儿子，可以记为 `-1`。

从 `v` 到重儿子的边叫重边，到其余孩子的边叫轻边。沿重边连续向下走形成一条重链；每条链最上方的节点叫链头。只有一个节点的链也是合法的重链。

主例中：

```text
size[3] = 1，size[2] = 1
size[1] = 2，size[0] = 4
heavy[0] = 1，heavy[1] = 3
```

因此有两条链：`0 → 1 → 3` 和单节点链 `2`。前一条链的链头是 `0`，后一条的链头是 `2`。

### 为什么一条路径只会跨过少量轻边？

设 `c` 是 `p` 的一个轻儿子，`h` 是 `p` 的重儿子。由于重儿子的子树最大，有 `size[h] ≥ size[c]`，所以：

```text
size[p] ≥ 1 + size[h] + size[c] ≥ 1 + 2 * size[c]
```

也就是说，**从父节点向轻儿子走，子树大小会减到原来的一半以下**。反过来，沿轻边向上走，子树大小至少翻倍。大小最多到 `n`，因此任何节点到根的路径最多经过 `O(log n)` 条轻边。

任意两点间的路径可以分成两条向公共祖先上行的路径，所以也只需要 `O(log n)` 个重链片段。

## 第二步：让同一条重链在数组中连续

为每个节点保存两个量：

| 数组 | 含义 |
|---|---|
| `head[v]` | 节点 `v` 所在重链的链头 |
| `pos[v]` | 节点 `v` 在展平数组中的位置 |

从根开始编号，每次先给当前节点编号，接着优先处理重儿子，最后再处理轻儿子的子树。重儿子继承当前链头，每个轻儿子则以自己为新链头。

因为沿重边时不会插入其他分支，同一条链的编号按从上到下的顺序连续递增。主例的一种结果是：

```text
数组位置：   0  1  2  3
节点编号：   0  1  3  2
初始点权：   5  4  2  3
链头编号：   0  0  0  2
```

在 `flat[pos[v]] = values[v]` 上建立区间最小值线段树。点赋值直接修改 `pos[v]`，剩下的问题是怎样拆查询路径。

## 第三步：每次取走链头更深的一段

设当前还没有处理的路径端点为 `u, v`，累积答案初始为正无穷。

当 `head[u] != head[v]` 时：

1. 比较两个链头的深度。如果 `depth[head[u]] < depth[head[v]]`，交换 `u, v`。
2. 查询闭区间 `[pos[head[u]], pos[u]]` 的最小值，并合并到答案中。
3. 令 `u = parent[head[u]]`，继续处理剩余路径。

这里比较的是**链头的深度**，不是端点的深度，也不是编号的大小。

### 为什么这一整段都在查询路径上？

两点不在同一条链时，链头更深的这一侧不可能越过两点的最近公共祖先。否则，这条链会包含那个祖先，而另一侧所在链的链头就必须更深，与选择矛盾。

因此，从 `u` 一直走到 `head[u]` 的节点都属于待查询路径。取走这一段后，跨过链头上方的轻边，剩余问题正好变成 `parent[head[u]]` 到 `v` 的路径。

被取走的节点不会再访问；如果两条链头深度相同，选任意一侧都可以。该过程也不会把根的父节点 `-1` 当作下一端点：两条不同链中，根所在链的链头深度最小，不会在此时被向上移出树。

### 两点终于在同一条链时

当 `head[u] == head[v]`，剩余路径就在一条链上。取两者位置的较小值和较大值，查询：

```text
[min(pos[u], pos[v]), max(pos[u], pos[v])]
```

把这一段的最小值合并后，查询结束。它包含当前两个端点，因此也包含原路径的 LCA。整个过程中不需要另外调用 LCA 函数。

若线段树使用半开区间，上述每个闭区间 `[L, R]` 都应转换为 `[L, R + 1)`。

## 按主例跟踪一次拆分

查询节点 `3` 到节点 `2`，两者链头分别是 `0` 和 `2`：

| 步骤 | 处理的节点段 | 数组闭区间 | 段最小值 |
|---|---|---|---|
| 链头 `2` 更深，先取这一侧 | 单节点 `2` | `[3, 3]` | `3` |
| 把这一侧移到 `parent[2] = 0` | 剩余路径为 `0` 到 `3` | 尚未查询 | — |
| 两端链头同为 `0`，处理最后一段 | `0 → 1 → 3` | `[0, 2]` | `2` |

合并后答案为 `min(3, 2) = 2`。节点 `0` 在最后一段出现一次，两个片段也没有重叠。

## 实现顺序与复杂度

<details>
<summary>实现提示：把两次树遍历拆开检查</summary>

第一次遍历记录父节点、深度和一个“父节点先于孩子”的访问顺序。再倒序处理这些节点，累加孩子的子树大小并选择重儿子。不要用节点编号的倒序代替遍历顺序，因为父编号不保证小于子编号。

第二次遍历分配链头和位置。可用显式栈保存待处理的链头；每取出一个链头，就沿重儿子一直走，连续分配位置，并把沿途的轻儿子压栈，留作后续的新链。

两次遍历均为 `O(n)`。这种写法也能处理长链，不依赖深度达到 `n` 的函数递归。

</details>

每次跨链都跨过一条轻边，因此每条查询路径只拆出 `O(log n)` 段。每段在线段树中查询 `O(log n)`，合起来为 `O(log² n)`；点赋值只修改一个位置，为 `O(log n)`。

若有 `a` 次赋值和 `q` 次查询，总时间为 `O(n + a log n + q log² n)`。所有剖分数组和线段树占用 `O(n)` 辅助空间，另需 `O(q)` 空间保存答案。

## 检查与运行

编辑 [exercises/14.cppm](../exercises/14.cppm)，重点检查：

1. 单节点路径返回该节点当前点权，包括它为负数或正数的情况。
2. 同链路径、跨两条链的路径，以及经过根的路径。
3. LCA 恰好具有最小点权，确保没有漏掉它。
4. 点权被改大、改小或保持不变后，所有相关路径都应使用新值。
5. 长链、星形树、多个孩子子树大小相同，以及父编号大于子编号的树。
6. 空操作列表、只有修改的列表，以及同一对象的多次调用。

在项目的 Nix 开发环境中运行：

```bash
./judge 14
```

最后解释：为什么必须优先处理链头更深的一侧？为什么轻边向下使子树大小至少减半，而向上则使子树大小至少翻倍？这两个理由分别保证路径拆分正确和段数足够少。
