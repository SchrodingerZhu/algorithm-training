# 21 · 独立练习：目录树的挂接、拆分与空间统计

一个文件系统有 n 个目录，编号为 `0..n-1`。每个目录中直接存放的文件共占 values[u] 字节，这个数不包含子目录中的文件。初始目录之间没有父子关系，各自是一棵目录树。

管理员可以挂接一棵独立目录树，也可以拆出一个目录及其后代。请维护这些操作，并查询一个目录及其全部后代占用的总字节数。每个目录至多有一个父目录，目录关系始终不能形成环。

## 题目与接口

```cpp
std::vector<long long> directorySum(
    const std::vector<long long>& values,
    const std::vector<std::array<long long, 3>>& operations);
```

初始所有节点都是独立目录树，编号 `0..n-1`。

| 操作 | 含义 |
|---|---|
| `{0,u,v}` | 若 u 是一棵树的根，且 u、v 不连通，将 u 挂为 v 的最后一个孩子；否则忽略 |
| `{1,u,0}` | 删除 u 与当前父目录之间的边，使 u 及后代独立；u 已是根则忽略 |
| `{2,u,w}` | 将 u 自己的占用赋为 w |
| `{3,u,0}` | 查询 u 及全部后代的占用和，包含 u 自己 |

返回类型 3 的答案。`1 ≤ n = values.size() ≤ 100000`，操作数不超过 200000，初始和赋值大小在 `[0,10⁹]`，单位为字节。类型与编号合法，保留字段为 0。没有查询返回空数组；同一对象多次调用相互独立。目标为每次期望 `O(log n)`，辅助空间 `O(n)`。

```text
values = [10,20,30,40]
operations = [[0,1,0], [0,2,1], [3,0,0], [3,1,0],
              [0,1,3], [3,3,0], [1,1,0], [0,1,3], [2,2,5], [3,3,0]]
answer = [60,50,40,65]
```

先形成 `0→1→2` 和独立的 3。第一次把 1 挂到 3 下被忽略，因为 1 不是根。拆出 1 后再挂接成功，最后 3 的目录树占用为 `40+20+5=65`。

返回数组按查询出现的顺序排列，不需要 main 或输入输出。可以先独立思考，再展开下面的实现提示。

<details><summary>实现提示：有根树的进入/退出序列</summary>

第 13 题的静态 DFS 区间不能直接应对移动；这里使用第 19 题的动态序列容器，但改为进入/退出记录，保留实际的父子方向。

## 第一步：每个节点写两张卡片

DFS 进入 u 时写 `in(u)`，走完全部孩子后写 `out(u)`。例子：0 的孩子是 1、2，1 的孩子是 3。

```text
in(0) in(1) in(3) out(3) out(1) in(2) out(2) out(0)
      |------ 1 的子树 ------|
```

从 `in(u)` 到 `out(u)` 的闭区间，恰好包含 u 及每个后代的两张卡片。因为 DFS 进入 u 后，会走完它的全部后代才退出，期间不会访问外部目录。

每张卡片是第 19 题中的一个 Treap 节点。保存固定句柄 `enter[u]`、`leave[u]`；它们一直指向同两张卡片，排名则随移动变化。初始 u 的序列是 `[in(u),out(u)]`，每棵目录树单独占一棵 Treap。

`in(u)` 的值为 `values[u]`，`out(u)` 的值为 0。这样每个目录直接存放的字节数只计一次；两张卡片都赋权会使答案翻倍。`size` 仍统计卡片数量，不能只统计非零权值卡片。

## 第二步：查询与赋值

先通过 enter[u] 找到所在 Treap 的根，再计算 `l=rank(enter[u])`、`r=rank(leave[u])`。先 `split(T,l)`，再把后半段按 `r-l+1` 切分，分离闭区间 `[l,r]`；读取第 20 题介绍的 sum，再拼回原序列。

赋值时只修改 enter[u] 的 value，然后从该节点开始沿普通 Treap 父链，逐个 `pull` 到根。没有 lazy 标记，因此只需自下而上修复。不要把目录整棵子树的和写入 enter[u]。

## 第三步：挂接整棵树

另外保存实际目录父亲 `directoryParent[u]`，初始为 -1。它与 Treap 的 `parent` 不同：前者表示题目中的直接父目录，后者只用于维护序列。

先检查 `directoryParent[u]==-1`，再检查 `root(enter[u]) != root(enter[v])`。失败时什么都不改，尤其不要先拆走 u。检查也会挡住自环与成环。

设 u 的整条序列为 U。在 v 的 `out(v)` **之前**插入 U：

```text
T = root(enter[v])
k = rank(leave[v])
(A,B) = split(T,k)
T = merge(merge(A,U),B)
directoryParent[u] = v
```

这就是给 v 增加最后一个孩子。u 内部的父子关系不变，原来的成对括号也不变。

## 第四步：拆出一个子树

若 u 不是根，先算好 enter[u] 与 leave[u] 的当前排名。将整条序列切成 `A + U + C`，其中 U 包含两端卡片。将 A 与 C 拼回，U 留作独立 Treap，设 `directoryParent[u]=-1`。

所有后代的实际父亲都不变，所以不用遍历整个 U。后续可以通过任一 enter 句柄向上找到各自的新 Treap 根，无需给每个后代重写「所属树编号」。

## 为什么这个版本还不能直接换根？

考虑链 `0→1` 的括号序列 `in(0) in(1) out(1) out(0)`。若简单旋转到 in(1)，得到 `in(1) out(1) out(0) in(0)`，括号不再正确嵌套。

因此本题的括号表示只用于上述固定父子方向的挂接与拆分。第 19 题的环形游走可以循环移位，因为每条边都有两个方向的记录；这里的括号有不同的含义。不要把两个版本的卡片含义混用。

## 分段练习与提示

先写出一棵三节点树的卡片，再做查询和赋值；然后只做合法挂接；最后做拆分与无效操作检查。

<details><summary>如何判断子树查询是正确的？</summary>

初始每个节点有正确的一对括号。挂接把一段完整括号插入另一个节点的退出之前，拆分取出完整的括号区间，两者都保持嵌套不变量。每个节点仅在进入卡片上贡献权值，因此该区间和就是子树和。每次只切拼常数次，Treap 提供期望对数复杂度。全森林始终有 2n 张卡片。
